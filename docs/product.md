# Prompt Pane 产品规格

## 问题与目标

长时间使用 AI CLI 时，用户早先发送的提示词会被回答和工具输出淹没。Prompt Pane 提供一个始终可见、只包含本次运行用户提示词的伴随 pane。

`v1.1.0` 面向 Windows x64 上使用 PowerShell、Zellij 和 Codex CLI 的用户；终端只需能够正常运行受支持的 Zellij，不限定品牌。

## 用户路径

1. 首次使用或升级时，用户在 PowerShell 中执行 README 提供的一条安装命令；脚本下载并校验当前 Windows x64 Release，将程序安装到当前用户目录，再调用 `setup codex` 完成组件安装和完整诊断。重跑同一命令执行幂等升级，不要求 Go、Git、管理员权限或修改系统 `PATH`。
2. 用户运行 `codex.pp`；兼容入口 `prompt-pane codex` 继续可用，Codex 参数保持结构化 argv 原样转发。
3. 首次安装后，用户按完成提示运行 `codex.pp` 并提交第一条 prompt；如果右侧未显示，再在 Codex 中打开 `/hooks` 审查并信任 Prompt Pane，然后重新运行 `codex.pp`。程序不得代替用户信任 Hook，也不得把尚未提交首条 prompt 误判为 Hook 故障。
4. Prompt Pane 检查 Codex、插件、`codex.pp` 快捷入口和 Zellij；缺失或过期时列出受管组件并自动修复，成功后继续本次 Codex 启动，不要求用户确认或执行第二条修复命令。
5. Zellij 创建左 70%、右 30% 的工作区，左侧获得焦点且保持原有标题，右侧标题固定为 `PROMPTS`；保留窗格边框与鼠标 resize，但本次会话不显示边框悬停高亮和 resize 帮助文字，并将首次点击直通目标窗格，使用户不必先单独聚焦 viewer。Prompt Pane 不接管 Zellij 的边框主题。
6. 用户在左侧提交的提示词在 1 秒内显示到右侧。
7. 使用 Zellij 的退出操作时回到可正常使用的 PowerShell；直接关闭终端时结束当前 Prompt Pane 工作区及其中的 Codex，不在后台保留可重新连接的运行。

## 行为约束

1. 每次运行生成不可预测的 `run_id`、endpoint 和一次性 token。
2. 当前运行通过认证 IPC 与 Hook `session_id` 精确绑定，不选择最近文件。
3. 只接受官方 `UserPromptSubmit` 中的 prompt；不展示回答、推理、工具、权限、系统或开发者消息。
4. 按提交顺序显示，保留 Unicode、多行和有意义空白；相同文本的不同提交不得合并。
5. 新主会话、恢复或清空会话不读取旧提示词并清空右侧，只显示边界后新提交的提示词；上下文压缩不清空本次运行记录。`/side`／`/btw` 临时侧聊只覆盖正文：侧聊期间显示侧聊提示词并冻结保留父会话状态栏，返回父会话后的第一条 prompt 恢复父提示词并丢弃侧聊内容。
6. Hook 或 IPC 失败不得破坏 Codex 自身运行，也不得串到其他会话。
7. 位于底部时自动跟随；用户上滚后保持位置，直到主动返回最新项。
8. resize 后按新单元格尺寸重排，不能越界、重叠或破坏 Unicode。
9. 退出和异常路径恢复终端输入、光标和颜色；终端被关闭时必须退出本次 Zellij 会话及其 Codex、viewer 子进程，不得默认分离到后台。
10. 用户可直接在 viewer 正文中用鼠标拖选当前可见文字，无需先单击聚焦右侧窗格；松开左键后将所选文字发送到系统剪贴板。该操作不得读取隐藏内容或旧会话，不得写日志、配置、遥测、缓存或网络请求。
11. 除用户显式拖选产生的系统剪贴板内容外，prompt 只在本机内存和终端处理。
12. viewer 可显示当前准确会话的累计 token、上下文和 5h／7d 限额；这些指标只从结构化 usage 元数据取得，不得用于恢复、搜索或显示旧 prompt。
13. 用户可在帮助页预览并保存六套全局主题；主题配置只包含非敏感主题名称，应用范围不包含 Zellij 外层边框。

## 首版非目标

- 终端原生插件、终端源码修改或连接已运行的 Codex。
- Codex 之外的 provider。
- 全局历史浏览、搜索、编辑、删除、导出、收藏或同步。
- 数据库、后台 daemon、PowerShell Profile 修改。
- SSH、WSL、容器和远程会话。
- macOS／Linux 的正式支持承诺。

## 安装与升级要求

- GitHub 用户入口必须是一条兼容 Windows PowerShell 5.1 与 PowerShell 7 的命令；引导脚本只从项目 GitHub Release 下载 Windows x64 产物和摘要，不调用 GitHub API、不执行未校验的二进制，并支持显式固定版本。仓库、Release 或产物尚未公开时不得声称外部用户可以一键安装。
- 引导脚本必须先下载到临时目录、校验 SHA-256，再以原子替换安装到当前用户的 Prompt Pane 数据目录；下载、校验或安装失败时保留原有可用版本。脚本不得要求管理员权限、修改 PowerShell 执行策略、Profile 或系统 `PATH`。
- 引导脚本必须覆盖 Windows x64、PowerShell 5.1／7、TLS 1.2、PowerShell 当前代理配置、自定义 `PROMPT_PANE_HOME`、空格／中文／非系统盘路径、重复安装、固定版本、摘要不匹配、网络失败和正在使用的目标文件。组织策略禁止内联脚本时，README 必须提供先下载再执行的等价路径。受管 Zellij 下载只继承 `HTTP_PROXY`／`HTTPS_PROXY`／`NO_PROXY`；仅配置 Windows 系统代理而未导出这些环境变量时，不得声称已经适配，失败提示必须说明设置 `HTTPS_PROXY` 或预先安装准确版本 Zellij 的处理方式。
- 对用户只暴露一条 `prompt-pane setup codex` 初始化命令；程序列出需要处理的受管组件后，自动完成环境探测、兼容版本选择、下载校验、Codex 插件安装、`codex.pp` 快捷入口安装及与 `doctor` 相同的完整只读检查，不要求用户确认、逐步选择实现细节或另行运行诊断命令。完整检查失败时 setup 必须返回非零退出码，只有全部通过才显示启动命令。
- `setup codex` 和 `doctor` 必须明确校验 Windows x64 与可用的 PowerShell 5.1／7；Codex、用户配置目录和快捷入口通过系统接口及 `PATH` 发现，不假定用户名、盘符或 npm 安装位置，包含空格和中文的绝对路径必须可用。
- 下载或持久安装前，程序必须探测 Prompt Pane、Codex 配置和 `codex.pp` 目标目录的真实写入能力；权限不足时指出具体目标并停止，已经存在且与当前版本一致的受管组件不得重复改写。
- 下载和安装过程必须持续显示当前阶段；耗时下载提供可感知的进度、已传输量或无法获得总量时的活动状态，避免无输出等待。
- 下载主程序、摘要或 Zellij 失败时，错误必须指出失败组件和阶段，区分 GitHub 不可达、HTTP 状态、代理／TLS、摘要缺失或不匹配、目标不可写和文件占用，并给出一个直接可执行的处理方向；不得只输出底层异常或笼统的“安装失败”。通过 `irm ... | iex` 获取引导脚本本身的失败发生在程序运行前，由 README 说明 GitHub Raw 可达性和先下载再执行的替代入口。
- 交互终端在真实进度上方显示与操作语义匹配的反馈：首次安装以由慢到快的节奏让多列方块错峰下落到矩形底板位置，落位时向上轻微回弹一格，完成后让 `PROMPT PANE` 字形以终端背景色从底板中镂空；显式刷新直接逐行显示真实进度，不播放动画；启动前自动修复使用更紧凑、更短的局部落块反馈。没有受管组件需要更新时不播放动画。动画故障、非交互输出或空间不足时降级为普通进度，不得影响安装结果与错误可见性。
- `codex.pp` 安装到当前 `codex.cmd` 所在目录，调用同一 Prompt Pane 可执行文件并继续发现用户原有的 Codex CLI；不得覆盖同名非受管文件，不得修改 `codex.cmd`、PowerShell Profile 或 `PATH`。
- 环境差异优先由程序适配；只有缺少权限、网络不可用或存在不可安全替用户决定的冲突时，才停止并给出单一、可执行的处理说明。
- 已安装 `codex.pp` 后，日常启动必须复用与 `setup codex` 相同的检查和安装事务；全部就绪时静默启动，缺失或过期时列出待修复组件、自动完成修复并进入 Codex。修复失败时不得启动半就绪工作区。
- 当前单版本安装存在活动 Prompt Pane 工作区时，显式刷新或启动前自动修复必须在修改插件、`codex.pp` 或所有权状态前停止，并明确提示先关闭活动工作区；全部组件已经就绪的并发启动不受影响。插件、快捷入口和所有权状态属于同一刷新事务，任一步失败必须恢复刷新前的完整可用状态。

## 验收场景

### 新会话

运行 `codex.pp`，并用 `prompt-pane codex` 复验兼容入口；确认两者均创建 70/30 且左侧获得焦点。提交中文单行、多行、重复、超长、emoji 和含控制序列的文本；右侧按序安全显示且不出现其他消息。

### 并发隔离

两个独立终端同时启动，提交不同提示词；两个 viewer 不混合，错误 token 和错误 `run_id` 被拒绝。

### 会话边界

通过 `codex.pp resume`、兼容入口 `prompt-pane codex -- resume` 或 Codex 内 `/resume` 恢复会话。会话选择由 Codex 处理；恢复完成后右侧清空并提示只显示之后的新提示词，即使恢复事件沿用相同 `session_id` 也必须重置。`SessionStart(source=clear)` 使用相同清空语义；`SessionStart(source=compact)` 保留本次运行已经显示的提示词和阅读状态。当前主会话已结束后的不同 ID `startup` 表示进入新主会话并清空右侧；主会话仍为 live 时出现的不同 ID `startup` 先作为 `/side`／`/btw` 临时覆盖层，正文只显示侧聊 prompt，状态栏继续显示进入侧聊前的父会话指标且不接受侧聊指标覆盖。若侧聊产生 `SessionEnd` 则立即恢复父快照；否则在父 `session_id` 的下一条 `UserPromptSubmit` 到达时恢复父提示词、追加该 prompt 并销毁侧聊内容。相同 ID 的重复 `startup` 保留当前快照。除上述父会话返回信号外，跨 ID 切换后的迟到旧会话事件不得改变当前快照或状态；当前主会话收到 `SessionEnd` 后，迟到提示词必须静默丢弃且不得把 `[ENDED]` 恢复为 `[LIVE]`，直到新的有效 `SessionStart` 到达。第一条新提示词到达后清除边界提示。

### 临时侧聊

主会话已有 prompt 和指标后进入 `/side`／`/btw`，确认右侧正文切换为侧聊 prompt，但主会话指标继续可见且保持最后有效值。侧聊 `Stop` 不得覆盖父指标，缺少 `transcript_path` 时必须静默跳过指标更新而不能显示 Hook 失败。退出侧聊后若 Codex 未提供退出 Hook，右侧允许暂时保留侧聊正文；提交下一条父会话 prompt 后必须恢复进入侧聊前的父提示词、追加新 prompt、继续使用父指标并不再保留侧聊内容。真正的新主会话、`resume` 或 `clear` 仍清空提示词和指标。

### 视觉交互

按 `docs/ui.md` 在不同字号、行高、窗口宽度和固定测试尺寸下检查换行、滚动、自动跟随、鼠标点击选中、复制选择和响应式状态。

### 故障与退出

模拟 Hook 未信任、IPC 不可用、无效事件、迟到的旧会话事件、Codex 退出、viewer 提前退出和 Zellij 异常；确认 Codex 不被提示词面板故障阻塞，并能恢复 PowerShell。

`[READY]` 只表示 Hook 链路尚未被事件确认；在用户提交首条 prompt 前，右侧必须持续显示正常等待状态，不得按等待时长推断 Hook 故障。用户提交 prompt 后仍未显示时，可通过 Help 引导其在 Codex 中打开 `/hooks` 审查并信任 Prompt Pane，然后重新运行 `codex.pp`；不得自动写入信任状态或绕过 Codex 的信任检查。

### Windows x64 环境差异

在 PowerShell 5.1 与 7 的公共命令语法下，覆盖系统盘和非系统盘、空格和中文路径、自定义 `CODEX_HOME`／`PROMPT_PANE_HOME`、首次安装、重复安装、受管升级、同名非受管冲突和目录不可写；`doctor` 必须区分平台、PowerShell、Codex、插件、快捷入口和 Zellij 的状态。

保持一个 Prompt Pane 工作区运行并执行需要修改受管组件的 setup，确认命令在任何文件变化前失败并提示关闭活动工作区；组件全部就绪时确认多个工作区仍可并发启动。分别在插件切换、插件注册、`codex.pp` 切换和所有权状态写入阶段注入失败，确认命令返回非零，旧插件、快捷入口和所有权摘要恢复且重新验证通过，不出现混合版本。
