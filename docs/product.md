# Prompt Pane 产品规格

## 问题与目标

长时间使用 AI CLI 时，用户早先发送的提示词会被回答和工具输出淹没。Prompt Pane 提供一个始终可见、只包含本次运行用户提示词的伴随 pane。

`v1.1.0` 面向 Windows x64 上使用 PowerShell、Zellij 和 Codex CLI 的用户；终端只需能够正常运行受支持的 Zellij，不限定品牌。

## 用户路径

1. 用户在终端中打开 PowerShell 并进入工作目录。
2. 用户运行 `codex.pp`；兼容入口 `prompt-pane codex` 继续可用，Codex 参数保持结构化 argv 原样转发。
3. Prompt Pane 检查 Codex、插件、`codex.pp` 快捷入口和 Zellij；缺失或过期时列出受管组件并自动修复，成功后继续本次 Codex 启动，不要求用户确认或执行第二条命令。
4. Zellij 创建左 70%、右 30% 的工作区，左侧获得焦点。
5. 用户在左侧提交的提示词在 1 秒内显示到右侧。
6. 退出工作区后回到可正常使用的 PowerShell。

## 行为约束

1. 每次运行生成不可预测的 `run_id`、endpoint 和一次性 token。
2. 当前运行通过认证 IPC 与 Hook `session_id` 精确绑定，不选择最近文件。
3. 只接受官方 `UserPromptSubmit` 中的 prompt；不展示回答、推理、工具、权限、系统或开发者消息。
4. 按提交顺序显示，保留 Unicode、多行和有意义空白；相同文本的不同提交不得合并。
5. 新会话、恢复或清空会话不读取旧提示词并清空右侧，只显示边界后新提交的提示词；上下文压缩不清空本次运行记录。
6. Hook 或 IPC 失败不得破坏 Codex 自身运行，也不得串到其他会话。
7. 位于底部时自动跟随；用户上滚后保持位置，直到主动返回最新项。
8. resize 后按新单元格尺寸重排，不能越界、重叠或破坏 Unicode。
9. 退出和异常路径恢复终端输入、光标和颜色。
10. 用户可在 viewer 正文中用鼠标拖选当前可见文字；松开左键后将所选文字发送到系统剪贴板。该操作不得读取隐藏内容或旧会话，不得写日志、配置、遥测、缓存或网络请求。
11. 除用户显式拖选产生的系统剪贴板内容外，prompt 只在本机内存和终端处理。
12. viewer 可显示当前准确会话的累计 token、上下文和 5h／7d 限额；这些指标只从结构化 usage 元数据取得，不得用于恢复、搜索或显示旧 prompt。
13. 用户可在帮助页预览并保存六套全局主题；主题配置只包含非敏感主题名称。

## 首版非目标

- 终端原生插件、终端源码修改或连接已运行的 Codex。
- Codex 之外的 provider。
- 全局历史浏览、搜索、编辑、删除、导出、收藏或同步。
- 数据库、后台 daemon、PowerShell Profile 修改。
- SSH、WSL、容器和远程会话。
- macOS／Linux 的正式支持承诺。

## 后续安装体验要求

- 对用户只暴露一条 `prompt-pane setup codex` 初始化命令；程序列出需要处理的受管组件后，自动完成环境探测、兼容版本选择、下载校验、Codex 插件安装、`codex.pp` 快捷入口安装及与 `doctor` 相同的完整只读检查，不要求用户确认、逐步选择实现细节或另行运行诊断命令。完整检查失败时 setup 必须返回非零退出码，只有全部通过才显示启动命令。
- `setup codex` 和 `doctor` 必须明确校验 Windows x64 与可用的 PowerShell 5.1／7；Codex、用户配置目录和快捷入口通过系统接口及 `PATH` 发现，不假定用户名、盘符或 npm 安装位置，包含空格和中文的绝对路径必须可用。
- 下载或持久安装前，程序必须探测 Prompt Pane、Codex 配置和 `codex.pp` 目标目录的真实写入能力；权限不足时指出具体目标并停止，已经存在且与当前版本一致的受管组件不得重复改写。
- 下载和安装过程必须持续显示当前阶段；耗时下载提供可感知的进度、已传输量或无法获得总量时的活动状态，避免无输出等待。
- 交互终端在真实进度上方显示与操作语义匹配的反馈：首次安装以由慢到快的节奏让多列方块错峰下落到矩形底板位置，落位时向上轻微回弹一格，完成后让 `PROMPT PANE` 字形以终端背景色从底板中镂空；显式刷新直接逐行显示真实进度，不播放动画；启动前自动修复使用更紧凑、更短的局部落块反馈。没有受管组件需要更新时不播放动画。动画故障、非交互输出或空间不足时降级为普通进度，不得影响安装结果与错误可见性。
- `codex.pp` 安装到当前 `codex.cmd` 所在目录，调用同一 Prompt Pane 可执行文件并继续发现用户原有的 Codex CLI；不得覆盖同名非受管文件，不得修改 `codex.cmd`、PowerShell Profile 或 `PATH`。
- 环境差异优先由程序适配；只有缺少权限、网络不可用或存在不可安全替用户决定的冲突时，才停止并给出单一、可执行的处理说明。
- 已安装 `codex.pp` 后，日常启动必须复用与 `setup codex` 相同的检查和安装事务；全部就绪时静默启动，缺失或过期时列出待修复组件、自动完成修复并进入 Codex。修复失败时不得启动半就绪工作区。

## 验收场景

### 新会话

运行 `codex.pp`，并用 `prompt-pane codex` 复验兼容入口；确认两者均创建 70/30 且左侧获得焦点。提交中文单行、多行、重复、超长、emoji 和含控制序列的文本；右侧按序安全显示且不出现其他消息。

### 并发隔离

两个独立终端同时启动，提交不同提示词；两个 viewer 不混合，错误 token 和错误 `run_id` 被拒绝。

### 会话边界

通过 `codex.pp resume`、兼容入口 `prompt-pane codex -- resume` 或 Codex 内 `/resume` 恢复会话。会话选择由 Codex 处理；恢复完成后右侧清空并提示只显示之后的新提示词，即使恢复事件沿用相同 `session_id` 也必须重置。不同 ID 的 `SessionStart(source=startup)` 表示同一次 `codex.pp` 运行内进入新会话，也必须清空右侧；相同 ID 的重复 `startup` 保留当前快照。`SessionStart(source=clear)` 使用相同清空语义；`SessionStart(source=compact)` 保留本次运行已经显示的提示词和阅读状态。跨 ID 切换后迟到的旧会话事件不得改变当前快照或状态；当前会话收到 `SessionEnd` 后，迟到提示词必须静默丢弃且不得把 `[ENDED]` 恢复为 `[LIVE]`，直到新的有效 `SessionStart` 到达。第一条新提示词到达后清除边界提示。

### 视觉交互

按 `docs/ui.md` 在不同字号、行高、窗口宽度和固定测试尺寸下检查换行、滚动、自动跟随、鼠标点击选中、复制选择和响应式状态。

### 故障与退出

模拟 Hook 未信任、IPC 不可用、无效事件、迟到的旧会话事件、Codex 退出、viewer 提前退出和 Zellij 异常；确认 Codex 不被提示词面板故障阻塞，并能恢复 PowerShell。

Hook 尚未信任时，右侧等待约 10 秒后必须提示用户在 Codex 中打开 `/hooks` 审查 Prompt Pane，然后重新运行 `codex.pp`；不得自动写入信任状态或绕过 Codex 的信任检查。

### Windows x64 环境差异

在 PowerShell 5.1 与 7 的公共命令语法下，覆盖系统盘和非系统盘、空格和中文路径、自定义 `CODEX_HOME`／`PROMPT_PANE_HOME`、首次安装、重复安装、受管升级、同名非受管冲突和目录不可写；`doctor` 必须区分平台、PowerShell、Codex、插件、快捷入口和 Zellij 的状态。
