# Prompt Pane 产品规格

## 问题与目标

长时间使用 AI CLI 时，用户早先发送的提示词会被回答和工具输出淹没。Prompt Pane 提供一个始终可见、只包含本次运行用户提示词的伴随 pane。

`v1.2.0` 面向 Windows x64 上使用 PowerShell、Zellij 和 Codex CLI 的用户；终端只需能够正常运行受支持的 Zellij，不限定品牌。

## 用户路径

1. 首次使用或升级时，用户在 PowerShell 中执行 README 提供的一条安装命令；脚本下载并校验当前 Windows x64 Release，将程序安装到当前用户目录，再调用 `setup codex` 完成组件安装和完整诊断。重跑同一命令执行幂等升级，不要求 Go、Git、管理员权限或修改系统 `PATH`。
2. 用户运行 `codex.pp`；兼容入口 `prompt-pane codex` 继续可用，Codex 参数保持结构化 argv 原样转发。
3. 首次安装后，用户按完成提示运行 `codex.pp` 并提交第一条 prompt；如果右侧未显示，再在 Codex 中打开 `/hooks` 审查并信任 Prompt Pane，然后重新运行 `codex.pp`。程序不得代替用户信任 Hook，也不得把尚未提交首条 prompt 误判为 Hook 故障。
4. Prompt Pane 检查 Codex、插件、`codex.pp` 快捷入口和 Zellij；缺失或过期时列出受管组件并自动修复，成功后继续本次 Codex 启动，不要求用户确认或执行第二条修复命令。
5. Zellij 创建左 70%、右 30% 的工作区，左侧获得焦点且保持原有标题，右侧标题固定为 `PROMPTS`；保留窗格边框与鼠标 resize，但本次会话不显示边框悬停高亮和 resize 帮助文字，并将首次点击直通目标窗格，使用户不必先单独聚焦 viewer。Prompt Pane 不接管 Zellij 的边框主题。
6. 用户在左侧提交的提示词在 1 秒内显示到右侧。
7. 使用 Zellij 的退出操作时回到可正常使用的 PowerShell；直接关闭终端时结束当前 Prompt Pane 工作区及其中的 Codex，不在后台保留可重新连接的运行。

## 行为约束

1. 每次运行生成不可预测的 `run_id`、endpoint 和一次性 token。
2. 当前运行通过认证 IPC 与 Hook `session_id` 精确绑定，不选择最近文件。
3. 只接受官方 `UserPromptSubmit` 中的 prompt；每次 Hook 调用对应一条显示记录，不展示回答、推理、工具、权限、系统、开发者消息或未触发该 Hook 的控制命令。
4. 按提交顺序显示，保留 Unicode、多行和有意义空白；相同文本或相同 `turn_id` 的不同提交都不得合并。`turn_id` 只用于关联轮次完成，不作为提示词唯一标识。
5. 新主会话、恢复或清空会话不读取旧提示词并清空右侧，只显示边界后新提交的提示词；上下文压缩不清空本次运行记录。`/side`／`/btw` 的无 transcript ephemeral startup 临时覆盖正文：侧聊期间显示侧聊提示词并冻结保留父会话状态栏，返回父会话后的第一条 prompt 恢复父提示词并丢弃侧聊内容；带 transcript 的不同 ID `startup` 属于 `/new`、普通 `/fork` 等新主会话，不得误判为侧聊。
6. Hook 或 IPC 失败不得破坏 Codex 自身运行，也不得串到其他会话。viewer 已有 prompt 时仍必须显示自然语言错误说明并优先于指标或下方内容提示，不用状态码代替；ended／error 不得继续显示“首次回复后显示指标”这类未来承诺。
7. 位于底部时自动跟随；用户上滚后保持位置，直到主动返回最新项。
8. resize 后按新单元格尺寸重排，不能越界、重叠或破坏 Unicode。
9. 退出和异常路径恢复终端输入、光标和颜色；终端被关闭时必须退出本次 Zellij 会话及其 Codex、viewer 子进程，不得默认分离到后台。
10. 用户可直接在 viewer 正文中用鼠标拖选当前可见文字，无需先单击聚焦右侧窗格；松开左键后将所选文字发送到系统剪贴板。该操作不得读取隐藏内容或旧会话，不得写日志、配置、遥测、缓存或网络请求。
11. 除用户显式拖选产生的系统剪贴板内容外，prompt 只在本机内存和终端处理。
12. viewer 可显示当前准确会话的累计 token、上下文和默认 Codex 额度桶的窗口；多额度桶同时存在时固定选择 `limit_id == "codex"`，不得让 Spark 等具名特殊桶覆盖默认桶，旧版单桶也只接受同一 `limit_id`。窗口名称由结构化 usage 元数据给出的真实分钟数生成，`300` 分钟显示为 `5h`，`10080` 分钟显示为 `7d`，不存在的窗口不伪造。默认桶缺失、额度元数据缺失或结构不受支持时，必须保留其他有效指标并在主状态栏省略额度组；Settings 中的 Help 必须说明额度未显示代表 Codex 当前没有提供可可靠显示的数据，不影响 Codex 使用。这些指标不得用于恢复、搜索或显示旧 prompt。
13. 用户可按 `s` 打开 Settings 页面；首页统一提供 Theme、Language、Help 和 About 四个入口。Theme 支持通过方向键或单击主题行预览，按 Enter 保存并返回 Settings；`Esc` 取消预览并恢复原主题。Help 只保留连接排障、操作与指标说明；About 独立显示 Prompt Pane 版本、完整支持环境、固定 Zellij 版本和 Token Tracker 视觉来源。各子页通过 `Esc` 返回 Settings，主题配置只包含非敏感主题名称，应用范围不包含 Zellij 外层边框。
14. 每条新提示词从提交约 300ms 后在自身尾部行显示轻量等待动效：只显示短句、一个半角空格和固定三格的 `空白 → . → .. → ... → 空白` 点号动画，不显示前置粒子。动效持续到同一 `session_id + turn_id` 的 `Stop` 到达，或当前轮次的结构化终止记录确认正常结束、中断、替换或预算停止。新提示词、会话结束、错误、恢复或清空必须立即使旧轮次失效；结构化指标不可用不得阻止动效结束。
15. 等待动效只表达仍在探索，不显示、概括或推断回答内容，不声明已经找到结果或预计完成时间。中文文案采用 Claude Code 式短动作词，在泛中文口语、真实方言、网络流行语、文言／典故／诗词和古今混搭之间随机轮换；文案选择不得读取 prompt，内部语体与方言标签不向用户暴露为 Activity style 设置。
16. 尚无已保存语言偏好时，界面按当前 Windows 用户首选 UI 语言选择默认值：首选语言属于中文语言族时使用中文，其余语言使用英文；检测失败或未返回语言时回退中文。用户可在 Settings 中于中文与英文间切换并保存，已保存偏好始终优先于系统检测。切换必须同时作用于等待文案、空状态、会话提示、Help 中的额度说明、设置、帮助、关于、主题页、折叠与滚动提示，以及状态栏和页面底栏中的页面名、操作提示与自然语言说明。用户原始 prompt 保持原文；状态栏不显示会话状态码，`Total`、额度窗口标签、`Ctx`、模型与推理强度值、Git 分支和统计保持稳定原文。配置使用 `interface_language` 保存非敏感的 `zh`／`en` 语言代码；升级时兼容读取旧 `activity_language`，下一次保存任一偏好后只保留新键。不保存系统语言、当前短句、路线、随机种子、prompt 或轮次历史。

## Codex 输入映射

- 普通提交和任务运行期间排队／转向的用户输入都会逐次触发 `UserPromptSubmit`；后者可以共享当前 `turn_id`，Prompt Pane 仍逐条显示，并只让最新一条显示等待动效。
- `/plan <请求>` 先切换 Plan 模式，再把 `<请求>` 作为用户输入提交，因此显示 Hook 实际提供的请求正文；不带请求的 `/plan` 只切换模式，不新增记录。
- `/side <请求>`／`/btw <请求>` 在 ephemeral 会话中提交请求并临时覆盖正文；不带请求时只建立侧聊，收到后续用户输入才新增记录。
- `/new [名称]` 和 `/fork [名称]` 的名称属于会话控制参数，不是 prompt；新持久会话的下一条用户输入从空列表开始显示。
- `/goal`、`/goal <目标>`、`/goal clear`、`/goal pause` 和 `/goal resume` 走 Codex 目标控制面，不触发 `UserPromptSubmit`，因此不伪装成提示词。除非 Codex 后续提供能精确绑定目标正文的官方事件，否则 Prompt Pane 不读取 transcript 或其他内部状态补录。

## 首版非目标

- 终端原生插件、终端源码修改或连接已运行的 Codex。
- Codex 之外的 provider。
- 全局历史浏览、搜索、编辑、删除、导出、收藏或同步。
- 数据库、后台 daemon、PowerShell Profile 修改。
- SSH、WSL、容器和远程会话。
- macOS／Linux 的正式支持承诺。

## 安装与升级要求

- GitHub 用户入口必须是一条兼容 Windows PowerShell 5.1 与 PowerShell 7 的命令；引导脚本只从项目 GitHub Release 下载 Windows x64 产物和摘要，不调用 GitHub API、不执行未校验的二进制，并支持显式固定版本。仓库、Release 或产物尚未公开时不得声称外部用户可以一键安装。
- 引导脚本必须先下载到临时目录、校验 SHA-256，再执行已经校验的程序完成用户级安装。程序按内容摘要写入不可变版本目录，通过原子安装状态区分当前版本、等待启用版本和上一可用版本；下载、校验、暂存或激活失败时保留原有可用版本。脚本不得要求管理员权限、修改 PowerShell 执行策略、Profile 或系统 `PATH`。
- 引导脚本必须覆盖 Windows x64、PowerShell 5.1／7、TLS 1.2、PowerShell 当前代理配置、自定义 `PROMPT_PANE_HOME`、空格／中文／非系统盘路径、重复安装、固定版本、摘要不匹配、网络失败、运行中升级和正在使用的旧版本文件。组织策略禁止内联脚本时，README 必须提供先下载再执行的等价路径。受管 Zellij 下载只继承 `HTTP_PROXY`／`HTTPS_PROXY`／`NO_PROXY`；仅配置 Windows 系统代理而未导出这些环境变量时，不得声称已经适配，失败提示必须说明设置 `HTTPS_PROXY` 或预先安装准确版本 Zellij 的处理方式。
- 对用户只暴露一条 `prompt-pane setup codex` 初始化命令；程序列出需要处理的受管组件后，自动完成环境探测、兼容版本选择、版本暂存、Codex 插件安装、稳定入口安装及适用检查，不要求用户确认、逐步选择实现细节或另行运行诊断命令。首次安装或立即激活必须通过与 `doctor` 相同的完整只读检查后才显示启动命令；运行中升级只验证等待版本及状态且明确提示尚未激活，不能冒充完整安装已经生效。存在等待版本时，无论 `doctor` 由稳定入口还是等待版本二进制启动，现有插件都必须与安装状态中的当前版本核对，等待版本只核对文件和摘要，不得把正常的当前插件误报为未安装或禁用。
- `setup codex` 和 `doctor` 必须明确校验 Windows x64 与可用的 PowerShell 5.1／7；Codex、用户配置目录和快捷入口通过系统接口及 `PATH` 发现，不假定用户名、盘符或 npm 安装位置，包含空格和中文的绝对路径必须可用。
- 下载或持久安装前，程序必须探测 Prompt Pane、Codex 配置和 `codex.pp` 目标目录的真实写入能力；权限不足时指出具体目标并停止，已经存在且与当前版本一致的受管组件不得重复改写。
- 下载和安装过程必须持续显示当前阶段；耗时下载提供可感知的进度、已传输量或无法获得总量时的活动状态，避免无输出等待。
- 下载主程序、摘要或 Zellij 失败时，错误必须指出失败组件和阶段，区分 GitHub 不可达、HTTP 状态、代理／TLS、摘要缺失或不匹配、目标不可写和文件占用，并给出一个直接可执行的处理方向；不得只输出底层异常或笼统的“安装失败”。通过 `irm ... | iex` 获取引导脚本本身的失败发生在程序运行前，由 README 说明 GitHub Raw 可达性和先下载再执行的替代入口。
- 交互终端首次安装时在当前输出区域显示真实步骤列表：已完成、当前和未开始阶段使用不同标记，下载阶段只显示实际字节进度及可计算的下载百分比，不显示把不同耗时阶段机械等分的总百分比。显式刷新、非交互输出和重定向输出逐行显示真实阶段；启动前自动修复只显示当前活动阶段并在完成后紧凑收束。动态反馈或终端渲染故障不得影响安装事务、成功判断和错误可见性。
- `codex.pp` 安装到当前 `codex.cmd` 所在目录，作为稳定受管入口解析当前版本并继续发现用户原有的 Codex CLI；不得覆盖同名非受管文件，不得修改 `codex.cmd`、PowerShell Profile 或 `PATH`。稳定入口与版本化运行程序仍来自同一个发布可执行文件，不增加第二种发布资产。
- 环境差异优先由程序适配；只有缺少权限、网络不可用或存在不可安全替用户决定的冲突时，才停止并给出单一、可执行的处理说明。
- 已安装 `codex.pp` 后，日常启动必须复用与 `setup codex` 相同的检查和安装事务；全部就绪时静默启动，缺失或过期时列出待修复组件、自动完成修复并进入 Codex。修复失败时不得启动半就绪工作区。
- 已经建立版本化安装后，显式升级在活动 Prompt Pane 工作区存在时必须完成新版暂存并返回成功，但不得修改当前版本指针、Codex 插件、稳定入口或其所有权状态；输出必须明确区分“已经暂存、等待启用”和“已经激活”。现有工作区及其仍在活动期间新开的工作区继续使用同一当前版本，不允许跨版本工作区并发。
- 所有旧工作区退出后的首次 `codex.pp` 或 `prompt-pane codex` 启动必须在创建新工作区前自动尝试激活等待版本。激活时以独占活动锁和更新门协调插件、当前版本指针、稳定入口及所有权状态；完整验证成功后才能启动新版，失败时恢复旧版并允许旧版继续启动。首次从旧的单版本布局迁移到稳定入口时仍可要求关闭全部活动工作区一次。
- 成功激活后保留上一可用版本的文件；下一次成功暂存不同版本时清理更早且未被引用的版本。清理是有边界的尽力操作，只能作用于受管版本目录；文件仍被占用或清理失败不得破坏当前版本、等待版本或本次升级结果。

## 验收场景

### 新会话

运行 `codex.pp`，并用 `prompt-pane codex` 复验兼容入口；确认两者均创建 70/30 且左侧获得焦点。提交中文单行、多行、重复、超长、emoji 和含控制序列的文本；右侧按序安全显示且不出现其他消息。

### 并发隔离

两个独立终端同时启动，提交不同提示词；两个 viewer 不混合，错误 token 和错误 `run_id` 被拒绝。

### 会话边界

通过 `codex.pp resume`、兼容入口 `prompt-pane codex -- resume` 或 Codex 内 `/resume` 恢复会话。会话选择由 Codex 处理；恢复完成后右侧清空并提示只显示之后的新提示词，即使恢复事件沿用相同 `session_id` 也必须重置。`SessionStart(source=clear)` 使用相同清空语义；`SessionStart(source=compact)` 保留本次运行已经显示的提示词和阅读状态。不同 ID 且带 transcript 的 `startup` 表示 `/new`、普通 `/fork` 等新持久主会话，无论旧主会话是否仍为 live 都清空右侧；不同 ID、无 transcript 且旧主会话仍为 live 的 `startup` 才作为 `/side`／`/btw` 临时覆盖层，正文只显示侧聊 prompt，状态栏继续显示进入侧聊前的父会话指标且不接受侧聊指标覆盖。若侧聊产生 `SessionEnd` 则立即恢复父快照；否则在父 `session_id` 的下一条 `UserPromptSubmit` 到达时恢复父提示词、追加该 prompt 并销毁侧聊内容。相同 ID 的重复 `startup` 保留当前快照。除上述父会话返回信号外，跨 ID 切换后的迟到旧会话事件不得改变当前快照或状态；当前主会话收到 `SessionEnd` 后，迟到提示词必须静默丢弃且不得恢复为 live，直到新的有效 `SessionStart` 到达。第一条新提示词到达后清除边界提示。

### 同轮输入与控制命令

在同一轮生成期间连续提交至少两条排队／转向输入，确认 Hook 可复用同一 `turn_id`，右侧仍按到达顺序保留每一条且只有最后一条显示等待动效；该轮完成后动效结束。分别验证 `/plan <请求>`、`/side <请求>`、`/btw <请求>`、`/new` 和 `/fork` 的上述输入与会话边界；验证 `/goal` 系列控制命令不产生伪造记录，后续普通用户输入仍正常显示。

### 临时侧聊

主会话已有 prompt 和指标后进入 `/side`／`/btw`，确认右侧正文切换为侧聊 prompt，但主会话指标继续可见且保持最后有效值。侧聊 `Stop` 不得覆盖父指标，缺少 `transcript_path` 时必须静默跳过指标更新而不能显示 Hook 失败。退出侧聊后若 Codex 未提供退出 Hook，右侧允许暂时保留侧聊正文；提交下一条父会话 prompt 后必须恢复进入侧聊前的父提示词、追加新 prompt、继续使用父指标并不再保留侧聊内容。真正的新主会话、`resume` 或 `clear` 仍清空提示词和指标。

### 视觉交互

按 `docs/ui.md` 在不同字号、行高、窗口宽度和固定测试尺寸下检查换行、滚动、自动跟随、鼠标点击选中、复制选择、等待动效和响应式状态。确认活动行只跟随最新提示词、回答结束后恢复为空白、迟到旧轮次事件不能清除新轮次动效，且 Prompt Pane 的拖选复制不包含活动行文字。

### 故障与退出

模拟 Hook 未信任、IPC 不可用、无效事件、迟到的旧会话事件、Codex 退出、viewer 提前退出和 Zellij 异常；确认 Codex 不被提示词面板故障阻塞，并能恢复 PowerShell。

内部 ready 状态只表示 Hook 链路尚未被事件确认，不作为状态码显示；在用户提交首条 prompt 前，右侧必须持续显示正常等待状态，不得按等待时长推断 Hook 故障。用户提交 prompt 后仍未显示时，可通过 Help 引导其在 Codex 中打开 `/hooks` 审查并信任 Prompt Pane，然后重新运行 `codex.pp`；不得自动写入信任状态或绕过 Codex 的信任检查。

### Windows x64 环境差异

在 PowerShell 5.1 与 7 的公共命令语法下，覆盖系统盘和非系统盘、空格和中文路径、自定义 `CODEX_HOME`／`PROMPT_PANE_HOME`、首次安装、重复安装、受管升级、同名非受管冲突和目录不可写；`doctor` 必须区分平台、PowerShell、Codex、插件、快捷入口和 Zellij 的状态。

保持一个 Prompt Pane 工作区运行并执行不同版本的 setup，确认新版写入独立版本目录并标记为等待启用，当前版本指针、插件和稳定入口不变；旧工作区仍在运行时再次启动，确认新工作区继续使用旧版。关闭全部旧工作区后的首次启动必须自动激活新版并通过完整检查。分别在版本暂存、插件切换、插件注册、当前版本指针和稳定入口所有权写入阶段注入失败，确认旧版仍可启动且不出现混合版本；连续暂存两个新版时只保留最后请求的等待版本。下一次成功升级只清理不再被当前、等待或回退状态引用且未占用的版本。
