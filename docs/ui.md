# Prompt Pane UI 规格

## 控制边界

Prompt Pane 控制终端单元格内的文字、颜色、换行、留白和滚动。字体、字号、字重、字间距和像素行高由终端统一控制，程序不得修改终端设置或依赖特定终端品牌。

## 统一网格与间距

viewer 的所有页面共享同一套终端网格，不为单个状态临时决定间距。统一参数为：左右内边距 1 个单元格、同一结构内部间隔 1 个单元格、并列信息列间隔 2 个单元格、独立内容块间隔 1 行。统一指相同关系使用相同间距，不要求编号槽、信息列和独立段落使用同一个数值。

- prompt 列表、空状态、会话边界提示、错误提示、帮助页和排障页的正文统一从窗口内容区第一行开始，不保留顶部空行，也不按视口高度动态垂直居中。
- 高度至少 10 行时，正文与状态栏之间固定保留 1 行；用户主动离开最新区域时，该行改为显示下方内容提示，不增加占用或移动正文。高度 3～9 行时取消固定空行并使用紧凑底栏；需要显示下方内容提示时优先保留提示与状态，暂时隐藏指标。高度少于 3 行时优先保留正文。Settings、Help、About 与 Theme 页面各自使用一行固定底栏，不显示会话状态；正文顶部已有 Settings、About 或 Theme 标题时，底栏不得重复页面名，只保留适用的页码与操作。Help 没有独立顶部标题，底栏保留随界面语言切换的页面名；页码和右侧上下文操作说明同样随界面语言切换。
- prompt 编号槽左右使用 1 个单元格。Settings／Help／About／Theme 区块标题保持左侧 1 格内边距，所有区块正文使用额外 2 格层级缩进；快捷键、设置项、主题名和无标签说明共享正文起点。选择箭头占用正文起点前的 2 格选择槽；快捷键／设置项／主题名与说明／当前值／色板构成独立信息列。窄栏可缩短说明文字，但不得破坏正文起点。
- 页面标题与后续区块、帮助页各区块、排障说明与后续步骤之间空 1 行；区块标题直接衔接所属正文或列表，同一快捷键列表的条目之间不空行。prompt 列表的相邻条目之间固定空 1 行。
- 底栏左侧状态或页面位置左对齐、当前主要操作右对齐，左右各保留 1 个单元格；不在底栏并列堆叠次要操作。
- 组合快捷键统一使用无额外空格的 `/`，例如 `h/Esc`、`↑/k` 和 `PgUp/PgDn`；快捷键／主题名列左对齐，说明／色板列左对齐，标签列宽由当前布局中的最长快捷键或主题名决定。

## 安装动画

- `setup codex` 显示需要处理的组件后直接执行，并在交互终端的当前输出区域内渲染步骤列表，不进入 alternate screen、不清除既有终端内容。标题固定为 `Prompt Pane setup`；每个实际阶段只占一行，已完成阶段使用 `✓`，当前阶段使用 spinner，未开始阶段使用 `○`。没有受管组件需要更新时直接显示已是最新状态并执行最终检查，不播放 spinner。
- 步骤列表只包含本次真实执行的环境检查、缺失组件安装与最终验证；首帧必须使用本次真实阶段数。阶段编号显示为 `[current/total]`，不再显示把不同耗时阶段机械等分的总百分比；已就绪组件不得伪装成正在安装。
- 只有能够获得真实总字节数的下载阶段显示单条进度条、下载百分比与 `downloaded / total`；进度条由实际字节比例决定且不得倒退。无法量化的环境检查、安装与验证只使用 spinner，不伪造百分比或预计时间。
- 标题、阶段名称、下载字节和错误正文使用主题正文色；当前 spinner、阶段编号和进度条填充使用主题焦点色，进度条空槽与未开始符号使用弱化色。完成阶段只给 `✓` 使用绿色，警告和失败只给对应符号与状态码使用黄／红色，普通说明不整行染色；`NO_COLOR` 下保留全部符号、文字和结构。
- 首次安装成功后将当前阶段转为 `✓`，留下稳定步骤记录，并依次显示 `Installation ready` 与 `Running final checks`；启动前自动修复只显示当前活动行，完成后在宽度允许时收束为单行 `Repair complete · Starting Codex…`。窄终端将完成文案拆成两行，不能截断关键状态；真实工作完成后的收尾不超过约 300ms。
- 显式刷新不使用交互步骤列表，继续逐行显示真实阶段与下载字节进度，事务完成后依次显示 `Refresh ready` 与 `Running final checks`。非交互输出、重定向输出和渲染初始化失败同样使用逐行文本进度；动态反馈不参与安装事务或成功判断。
- `[FAIL]` 后必须保留完整错误正文：先指出失败组件与阶段，再显示一个可执行处理方向。主程序／摘要下载提示检查 GitHub Release、网络或代理；Zellij 下载提示检查 GitHub 并在仅有系统代理时设置 `HTTPS_PROXY`，或预先安装准确版本 Zellij；权限、同名非受管文件、摘要不匹配和文件占用分别显示自身处理方向。窄终端可以换行但不得只留下错误码或笼统的 `setup failed`。
- 交互式安装与自动修复动画、状态和完成文案共享终端左边缘，不做横向居中；显式刷新继续使用相同左边缘逐行输出真实进度。首次安装事务结束显示 `Installation ready`／`Running final checks`；显式刷新按逐行进度结束后显示 `Refresh ready`／`Running final checks`，随后逐项输出完整诊断。首次安装全部通过后显示 `Setup complete.`，并依次说明运行 `codex.pp`、提交第一条 prompt，以及未显示时打开 `/hooks` 审查并信任 Prompt Pane；刷新路径只显示可以继续运行 `codex.pp`，不重复首次信任教学。启动前自动修复结束显示 `Repair complete · Starting Codex…`。
- 交互步骤列表必须在运行期间消费终端能力查询回复，并在退出前恢复终端状态，不得把 CSI 等协议回复泄漏给 Shell。

## 标准布局

```text
  1 为什么都有 .go？

  2 Bubble Tea 又是什么？

  3 从使用者角度考虑呢？使用者不需
    要安装这些吧？
    这事有点门道 ...

                                 [s] 设置
```

- 正文滚动，状态和帮助入口固定在底栏；日常 viewer 不显示品牌名或顶部标题栏。
- Zellij 保留窗格边框，左侧保持原有标题，右侧外层窗格固定显示 `PROMPTS`，不显示可执行文件路径；Prompt Pane 启动的会话关闭边框悬停高亮与 resize 帮助文字，不关闭鼠标 resize，并让首次聚焦点击同时传入目标窗格。
- 初始 pane 比例固定为 70/30；程序不根据终端品牌或宽度自动改变比例，用户需要时使用 Zellij 自带的 resize 操作手动调整。
- 左右各保留 1 个单元格内边距；不画内部全宽分隔线。
- 编号槽最少预留 2 位并右对齐，达到 100 条时再按需扩展；编号槽左右各保留 1 个单元格，使其与窗格边界和正文的间距对称，正文在 1～99 条期间不得因编号位数变化而移动；续行与正文对齐，不显示竖向分隔符。
- 所有 prompt 的编号和正文统一使用主题 `text`，默认保持常规字重；当前焦点 prompt 或最新提示词处于处理中时，编号与全部可见正文整体加粗，不为编号设置独立颜色、背景或 `>`。焦点与处理中状态重合时仍只使用同一种整体加粗。鼠标拖动产生的文字选区是另一种状态，使用下述独立前景、背景和可见性规则。
- 每条提示词末尾保留 1 行尾部行：历史提示词和静止状态为空白，最新活动提示词在该行显示等待动效，因此相邻提示词之间仍固定空 1 行且轮次结束不改变布局高度。尾部行不属于 prompt，不响应点击选中、折叠、行数统计或 Prompt Pane 拖选复制。编号和续行缩进保持不变，提示词内部保留用户输入的段落和有意义空行。
- 不画逐条完整边框，不显示时间、回答或工具活动。底部状态栏可显示当前会话的结构化 token、上下文、默认 `codex` 额度桶的窗口以及宽度允许时的模型信息。
- 单条提示词按终端显示宽度换行：由空白分隔的普通英文／数字单词优先整体移到下一行；中文、日文、韩文和 emoji 可以在字素边界继续填满当前行，不能因其与前方英文片段相邻而把整段移到下一行；只有单个英文／数字 token 本身超过可用宽度时才按字素簇安全拆分。换行后超过 8 行时默认保留前 6 行，并以弱化色显示剩余行数；当前焦点项再按可用显示宽度补充完整或紧凑的 `Enter expand` 操作。折叠只影响当前渲染，不修改或丢弃内存中的完整 prompt。
- 每条长提示词独立保存展开状态；`Enter` 只展开或折叠当前焦点项，`c` 折叠全部已展开项，不提供展开全部。
- resize、新事件和上下文压缩不得重置选择或各条提示词的展开状态；相同 `turn_id` 的多条排队／转向输入仍是具有独立选择与展开状态的多条提示词；`/side`／`/btw` 临时侧聊只覆盖正文，返回父会话后恢复父提示词；恢复、清空或进入新主会话时清空选择、展开状态和旧提示词。

## 等待动效

- 收到 `prompt.submitted` 后约 300ms，在最新提示词的尾部行显示一条短句和点号动画；同一 `turn_id` 再收到一条提示词时，已有正文保留，活动行立即移到具有新 `prompt_id` 的最后一条。只有准确匹配当前 `active_turn_id` 的正常完成或中断事件可以结束，`SessionEnd` 和错误状态立即清空。
- 活动行固定为 `<短句><一个半角空格><三格点号槽>`。点号槽按 `空白 → . → .. → ... → 空白` 循环；空白帧使用三个空格，其他帧尾部补空格，使四帧始终占 3 个单元格，整行不得左右抖动；正常节奏为 500ms／帧，不显示任何前置粒子。
- 首分钟文案每 8～14 秒更换一次，之后放慢到 15～25 秒；用户返回页面时只显示当前短句，不补播错过内容，不显示章节、进度或已经找到结果。正常完成可保留当前短句与完整 `...` 不超过 200ms 后恢复空白，新轮次和错误不得等待收尾。
- 尚无已保存语言偏好时，界面按 Windows 用户首选 UI 语言选择默认值：中文语言族使用中文，其余语言使用英文，检测失败或结果为空时回退中文。Settings 可切换并保存中文或英文，已保存偏好始终优先；语言切换同时作用于等待文案、全部页面文字，以及状态栏和页面底栏中的页面名、操作提示与自然语言说明。技术指标、模型／推理强度值和 Git 数据保持稳定原文。中文等待文案使用 Claude Code 式短动作词，不写连续故事或围绕同一物件批量扩写的场景旁白。实际选择目标为现代自然口语约 25%、现代原创趣味约 30%、方言约 15%、网络／技术表达约 15%、文言／典故／诗词化用约 10%、古今混搭约 5%；方言覆盖东北／北方、川渝和粤语并均分。语体和方言标签不显示，也不提供 Activity style 设置。
- 真实性与原创趣味分别判断：现代原创趣味、网络技术隐喻和古今混搭允许有意拟人、生造与语体错位，但必须一眼可懂且不得冒充真实方言或文言；方言必须使用该地区自然的词汇、语序、体貌和语气，不能把普通话趣味句换几个地方词或句尾语气词。每个方言池保持约 30% 自然表达与 70% Claude Code 式原创趣味，趣味来自真实方言骨架上的单个技术隐喻或意外转折，不依赖夸张口音、刻板印象或催促用户。网络表达不得依赖时政、地域攻击、短期热点或解释才能成立的梗；文言应使用可靠句法或典故，诗词类明确属于化用并保留进行中的动作，不直接堆叠整句名篇；古今混搭不归入真实文言。每句必须脱离前后文独立成立，不得产生政治、地域或文化歧义。
- 所有中文短句必须先符合对应语体真实的词汇搭配、语序、语气和口语节奏。Claude Code 式趣味通过在自然中文骨架中加入日常动作、拟人、意象错位或意外转折形成，不逐词翻译英文 spinner verb，不把技术词、方言词或文言词硬接到不成立的中文句法上。去掉思考场景后，句子骨架仍须能够独立成立；朗读拗口、需要解释笑点或主要依靠病句产生反差的文案直接淘汰。
- 自动测试只能证明语料数量、分类、宽度、去重和明确禁用内容，不能证明语言自然度与趣味质量。新增或修改语料必须逐句人工朗读审阅；方言表达没有可靠把握时核对真实语料或词典，不凭普通话语感推造。
- 每次换词可以跨语体跳转，不连续选择同一语体；完整语料池最近 96 句不得重复，小型校准语料至少跨过半个语料池才允许复用。中文短句推荐不超过 28 个显示单元格，硬上限为 38；文案选择不得读取 prompt，不显示章节、内部分类或选择进度，也不保存当前短句、语体、随机种子或历史。
- 活动短句与固定三格点号统一使用主题 `activity_indicator`；活动行不继承当前提示词的选择效果。`NO_COLOR` 保留文字与点号结构。`PROMPT_PANE_REDUCED_MOTION` 存在时启用减少动态模式，固定显示 `...` 并降低文案切换频率。
- 可用正文宽度不能完整容纳当前短句时，在字素边界截短短句并优先保留一个半角空格和完整三格点号槽；不得退回只显示装饰符号。活动行随最新提示词滚动，用户上滚后不在固定位置重复显示。

## 响应式布局

- 宽度至少 20 列：底栏在空间允许时按界面语言只显示中文 `[s] 设置` 或英文 `[s] settings`；20 列无法容纳英文动作时缩为 `[s]`，不得隐藏设置入口。不平铺 Help、Theme 或语言快捷键。用户主动离开最新区域时，在状态栏上方按界面语言显示中文“下方还有提示词／内容”或英文 `↓ <n> prompts below`／`↓ More below`。
- 宽度少于 20 列：按当前界面语言换行显示“窗格太窄”或 `Pane too narrow`，可用高度允许时不得因保留单行而截断提示；底部不显示会话状态码，允许留空。事件继续保留，恢复宽度后重排。
- 高度规则统一遵循“统一网格与间距”，不得由 prompt、帮助或排障页面各自定义降级行为。

任何可见行都不得超过可用显示宽度；换行和带颜色文本的截断必须按终端显示单元格计算，并完整保留或关闭 ANSI 样式序列。

## 状态

- ready：Codex 与 viewer 已启动，但尚未收到 Codex `SessionStart`，因此 Hook 链路还未被事件确认；Codex 可能要到首条 prompt 才创建逻辑 session，不能据此断定 Hook 未启用或未信任。无论等待多久，正文都按界面语言显示“等待第一条提示词”或 `Waiting for your first prompt`，不得自动替换为故障或重启引导。底栏按界面语言只显示 `[s] 设置` 或 `[s] settings`；Settings 中 Help 的“连接”／`Connection` 区块说明只有用户已经提交 prompt 但右侧仍未显示时，才依次在 Codex 中打开 `/hooks`、审查并信任 Prompt Pane、重新运行 `codex.pp`。
- live：已收到 `SessionStart`，提示词链路实时接收正常；尚无 prompt 时按界面语言显示“等待第一条提示词”或 `Waiting for your first prompt`。
- ended：会话已退出，保留最后快照；迟到提示词不得改变快照或恢复为 live。
- error：本次运行不能安全继续；没有 prompt 时正文显示本地化错误说明，已有 prompt 时在正文与底栏之间固定显示同一说明。错误说明优先于下方内容提示和指标，不能因为保留旧 prompt 而消失。

ready、live、ended 和 error 只用于内部生命周期判断，状态栏不显示任何会话状态码。用户通过正文中的等待、会话结束或错误说明理解当前结果。

主会话结束后的不同 ID `startup`、`resume` 或 `clear` 产生空快照时，live 正文显示新会话、恢复或清空完成，并说明只显示之后的新提示词；第一条新提示词到达后隐藏该提示。相同 ID 的重复 `startup` 不重置；`compact` 不显示边界提示，也不改变现有提示词和阅读状态。

`/side`／`/btw` 是临时正文覆盖层：父会话仍为 live 时收到不同 ID、`ephemeral=true` 的 `startup`，正文切换为侧聊 prompt，底栏继续显示进入侧聊前的父会话指标。侧聊指标不得替换、隐藏或把父指标重置为等待态。若退出侧聊没有 Hook，正文可保留侧聊最后快照；父会话下一条 prompt 到达时恢复父提示词并追加该 prompt，侧聊 prompt 不再保留。不同 ID 且 `ephemeral=false` 的 `/new`／普通 `/fork` startup 是新主会话，即使旧会话仍为 live 也必须清空正文和指标；`resume` 和 `clear` 使用各自的既有清空提示。

## 颜色与主题

- 全局颜色使用 Token Tracker 同源的六套主题：`mocha`、`latte`、`frappe`、`macchiato`、`nord`、`dracula`。八个彩色槽与 `overlay0`、`cell` 保持同源精确 Hex；Prompt Pane 额外使用各主题官方正文色 `text` 统一承载长正文与显式拖选前景。颜色值和下述语义映射不得近似替换。
- 主题统一作用于 prompt、焦点效果、文字选区、帮助与排障页、状态栏、Git 状态、setup／刷新反馈和错误状态，不允许页面内硬编码独立颜色。
- 默认主题为 `auto`：可确认浅色背景时使用 `latte`，其余情况使用 `mocha`。用户确认的主题名称保存到 Prompt Pane 用户配置；`PROMPT_PANE_THEME` 可临时覆盖。主题只作用于 Prompt Pane 自身，不修改 Zellij 外层边框主题。
- 真彩色终端使用精确 24-bit RGB；不支持时由渲染层降级到 256 色；`NO_COLOR` 下移除颜色并使用字重、文字和符号保持层级。终端返回可解析的实际背景 RGB 时，只在主题语义前景与该背景的 sRGB 对比度不低于 `4.5:1` 时给普通文字设置该前景；不足时文字退回终端正常前景色，页面标题和主要操作同时以字重保持层级，当前焦点与最新处理中 prompt 仍以整体加粗表达状态。进度字符和主题色板仍保留原主题色，数值、Git 符号和文案继续提供非颜色语义。终端未返回背景时保持精确主题色和既有非颜色语义，不猜测具体背景 Hex。
- 所有提示词编号、正文和普通标签使用主题 `text`；当前焦点 prompt 与最新处理中 prompt 的编号和可见正文整体加粗，编号不使用独立颜色。页面标题、主要操作和 Git 分支名继续使用主题强调色。折叠提示、重置时间等真正次要信息使用 `overlay0`。`NO_COLOR` 下以字重、文字和符号保持层级。
- 等待动效与 spinner、进度条共用主题进度强调色：深色主题使用各自 `sapphire`，Latte 使用 `mauve`。活动短句与点号保持同色，不得按语言、语体或方言改变颜色。
- 限额低于 50% 使用 `green`，50%～79% 使用 `yellow`，80% 及以上使用 `red`。环境主题覆盖等可恢复注意事项使用 `yellow`，错误正文以及语言或主题保存失败使用 `red`。
- 状态栏沿用 Token Tracker 的 Codex 语义映射：Git 分支名和末尾脏标记 `*` 使用 `red`，未跟踪数量 `?N` 使用 `mauve`，新增 `+N` 使用 `green`，删除 `-N` 使用 `red`；`Total:` 与 Token 数值整段使用 `peach`，模型／推理强度值使用 `red`，额度窗口标签、`Ctx:` 与重置时间使用 `pink`，百分比和进度条使用对应阈值色。
- Prompt Pane 文字选区使用主题官方 `text` 前景与 `cell` 背景；六套显式组合的 sRGB 对比度都不得低于 `4.5:1`。终端返回实际背景且 `cell` 与背景的对比度低于 `3:1` 时，选区额外使用下划线标明边界；不得为提高选区可见性设置整个窗格背景或改变用户终端的正常前景色。代码和测试中必须使用“焦点 prompt”与“文字选区”两个独立角色，不能用一个含混的 selection 角色承载两者。
- 不使用 Nerd Font 图标；颜色不得成为理解状态的唯一方式。

### 设置、帮助、关于与主题

- `s` 打开 Settings 首页，首页只包含 Theme、Language、Help 和 About 四项；中文界面显示“主题、界面语言、帮助、关于”，英文界面显示 `Theme`、`Language`、`Help`、`About`。`↑`／`↓` 或单击选择，`Enter` 打开页面或切换语言，`Esc` 关闭 Settings 并返回 viewer。选择移动时必须自动保证当前项可见，使 `20x6` 仍能进入第四项。Help、About 与 Theme 只能从 Settings 进入，不提供全局 `h`、`t`、`l` 快捷键。
- Settings 正文不常驻显示方向键、单击、`Enter` 或 `Esc` 说明；底栏不重复顶部页面名，只在右侧显示 `Esc 关闭` 或 `Esc close`。完整操作集中在 Help，页面本身依靠选择箭头与设置值表达可操作性；当前选中行的箭头、名称和设置值只使用整体加粗，不改变文字颜色。
- Theme 保存后返回 Settings；取消预览恢复原主题并返回 Settings。Help 与 About 中 `Esc` 返回 Settings，不直接关闭整个设置层级；返回后仍保持并显示原先选中的设置项。
- Help 不显示独立的 Help 顶部标题，直接从第一个适用区块开始；ready 状态下增加“连接”／`Connection` 区块，只用当前界面语言说明“先提交第一条 prompt；若未出现，则打开 `/hooks`、信任 Prompt Pane 并重启 `codex.pp`”，不先解释 Hook 确认机制。区块固定按连接、帮助页操作、设置页操作、页外提示词操作、指标说明、Git 状态、窗格操作排列；中文与英文使用对应标题。指标说明必须解释“额度未显示”代表 Codex 当前没有提供可可靠显示的额度数据，并明确这不影响 Codex 使用，不在主状态栏重复该提示。帮助页操作同时列出易按的 `↑`／`↓` 和兼容的 `PgUp`／`PgDn`，两组按键都按一整个可见正文页滚动。设置页操作集中说明方向键／单击选择、`Enter` 打开页面或切换语言、`Esc` 关闭。窄栏可缩短页外提示词区块标题，但必须保留“页外”／`outside` 含义。Git 状态先显示 `main* +12 -3 ?1` 完整示例，再按当前界面语言解释各部分，不在用户文案中使用 `HEAD`。窗格操作只列与当前 70/30 工作区直接相关的 Zellij 默认聚焦、鼠标／键盘 resize 和全屏操作；连续按键使用 `→`，并明确 resize 和全屏作用于当前聚焦 pane。
- About 是独立页面，按当前界面语言显示页面与区块标题，并完整列出 Prompt Pane 版本、`Windows x64`、`PowerShell 5.1/7`、`Codex CLI`、固定支持的 Zellij 版本和 Token Tracker 视觉来源；专有名称和版本号保持原样，不展示实现框架。窄栏无法容纳完整的 `Prompt Pane <version>` 时可以省略重复的产品名，但必须保留完整版本字符串。
- Help 与 About 内容超过视口时使用 `↑`／`↓`、`PgUp`／`PgDn` 或滚轮独立滚动；方向键和翻页键每次移动一整个可见正文页。Help 单页底栏左侧按界面语言显示“帮助”／`Help`，右侧显示 `Esc 返回` 或 `Esc back`；超过一页时左侧显示页面名与 `<current>/<total>`，右侧优先显示 `↑/↓ 翻页`／`↑/↓ scroll` 与返回操作，空间充足时同时显示 `PgUp/PgDn`。宽度不足 26 列时中文页名缩为“帮”且页码紧接页名，英文缩为 `H`。About 顶部已有页面标题，底栏不再重复“关于”／`About`：单页只显示右侧返回操作，多页左侧只显示 `<current>/<total>`，右侧使用与 Help 相同的翻页与返回操作。单页不得显示无效的滚动操作；不得为了完整页名或翻页键兼容提示隐藏方向键或返回操作。Help 与 About 不改变 prompt 的选择、展开、滚动或跟随状态。
- Theme 页面只包含六套可保存的内置主题和按界面语言显示的“界面预览”／`Interface preview`，不显示仅用于首次解析的 `auto`；当前配置为 `auto` 时，打开 Theme 直接选中按终端背景解析出的 `latte` 或 `mocha`，保存后写入该明确主题。列表不显示 `recommended`／`current` 或中英文同义标签，只用左侧箭头表示正在预览的主题；选中箭头和主题名整体加粗并使用当前预览主题的紫色选择语义，名称按最长主题动态对齐。每个主题后依次显示与 Token Tracker 相同的 `green`、`yellow`、`peach`、`red`、`blue`、`sapphire`、`mauve`、`pink` 八个 `■` 方形色块；空间允许时色块间留一格，窄栏紧凑排列，极窄栏允许由视口裁切而不得退回圆点或减少颜色。
- Theme 标题下显示一行简要操作说明，明确方向键或单击用于预览、`Enter` 保存、`Esc` 取消；文案按宽度逐级缩短但优先保留选择方式和 `Enter`，高度不超过 6 行时隐藏该正文说明，由固定底栏继续提供操作提示，避免挤占主题列表。
- Theme 中 `↑`／`↓` 或单击主题所在行切换并实时预览，`Enter` 原子保存、应用并返回 Settings，`Esc` 取消未保存预览并返回 Settings。鼠标拖动仍选择并复制文字，不触发主题切换；`PgUp`／`PgDn` 和滚轮滚动页面，键盘或鼠标切换主题时自动让当前主题保持可见，`20x6` 必须可完成预览与保存。
- Theme 顶部已有页面标题，底栏不再重复“主题”／`Theme`；超过一页时左侧只显示 `<current>/<total>`。右侧按界面语言显示预览／保存／取消说明，并始终保留方向键、`Enter` 和 `Esc` 三类操作；极窄栏统一压缩为 `↑↓ Enter Esc`，不得隐藏取消操作。主题列表后固定显示语义预览，空间允许时标题为“界面预览”／`Interface preview · <name>`，极窄栏只省略标题后的主题名，不隐藏预览内容，也不读取或复用真实会话内容。预览使用与 viewer 相同的编号槽、提示词间隔、整体加粗焦点、整体加粗最新处理中状态、活动尾部行、下方内容提示和两行状态栏排版，并使用简短的真实任务语句而不是“其他提示词／焦点提示词”等界面标注；文字选区直接覆盖第 2 条中的“边界条件”／`edge cases`。主预览与日常 viewer 一样不显示会话状态码，也不追加“其他状态”样本。示例中的操作性文字随界面语言切换，Total、5h／7d、模型值、Git 分支／增删／未跟踪和数值保持稳定原文；所有示例只随当前预览主题换色。
- `PROMPT_PANE_THEME` 生效时 Theme 显示环境覆盖来源；允许预览但不允许保存被覆盖的设置。
- 配置只保存主题名称和 `interface_language` 界面语言代码。语言代码限于 `zh`／`en`，控制 Prompt Pane 自有页面文案，以及状态栏和页面底栏中的页面名、操作提示与自然语言说明；用户 prompt、技术指标、模型／推理强度值和 Git 数据不翻译。首次默认语言读取 Windows 用户首选 UI 语言但不保存检测结果；读取时兼容旧 `activity_language`，新键优先；下一次保存主题或语言时迁移并只写 `interface_language`。配置不得包含系统语言、Activity style、prompt、会话指标、路径、凭据、当前短句、随机种子或历史。

## 状态栏

- 状态栏不显示 provider、项目名、Codex 原始 `limit_id`、额度桶名称或会话状态码。核心字段优先级为会话累计 `Total`、适用额度窗口、上下文 `Ctx`；宽度充足时显示分支、Git 增删、重置倒计时和模型／推理强度。模型／推理强度位于标题行时直接显示值，不重复显示 `Model:` 标签。
- `Total`、额度窗口标签、`Ctx`、模型与推理强度值、Git 分支和统计保持稳定原文；`[s] 设置`／`[s] settings`、Help 中的额度说明、页面名、其余页面的操作提示和自然语言说明随界面语言切换。
- Git 状态使用 `branch* +N -N ?N`：`branch` 是当前分支，`*` 表示已有已跟踪改动，`+N`／`-N` 是已暂存与未暂存的已跟踪文件相对 `HEAD` 累计增删行数，`?N` 是排除 ignore 规则后的未跟踪文件数；这些数字不是文件数或领先／落后的提交数。
- `Total` 使用 provider 当前会话累计值；恢复会话可包含恢复前的累计 token，但不得恢复或显示旧 prompt。新会话和 `clear` 清空指标，`compact` 保留。
- ready／live 首次收到 `Stop` Hook 指标前，状态栏指标区必须保留并按界面语言显示“首次回复后显示指标”或 `Metrics available after first response`，不得把尚未提交 prompt 的正常状态表述为正在等待 Codex 回答；ended／error 不显示这条未来承诺，error 优先显示错误说明并隐藏指标。已收到指标后，只显示默认 `codex` 额度桶实际提供的窗口，不显示 Spark 等其他具名桶；`300` 分钟显示为 `5h`，`10080` 分钟显示为 `7d`，其他窗口按真实分钟数生成最短整分钟／整小时／整天标签并按时长升序显示，不存在的窗口不伪造。额度状态为 `unavailable` 或 `available` 且窗口列表为空时，主状态栏都不显示额度组，并让上下文使用空出的空间；Help 的“指标说明”区块提供本地化解释。真实 `0%` 必须正常显示；`ContextWindow > 0` 时 `ContextUsedPercent = 0` 是有效的 `Ctx: 0%`，不能显示为未知。其他单个不可用字段显示 `--`，不得隐藏整个指标区或用 `0` 冒充未知值。整体指标解析失败时保留上一次有效值；新主会话、恢复会话和 `clear` 清空旧指标并重新进入等待状态，`compact` 保留，`/side`／`/btw` 继承并冻结父会话最后一次有效指标。额度颜色阈值与主题语义一致。
- 进度使用 Token Tracker 同款前景色字符：已用部分为 `█`，剩余部分为 `░` 点阵；不得使用背景色空格渲染成连续矩形色块。字段统一使用标签在前的 `Label: value` 语序，并按前述 Token Tracker 状态栏语义映射给标签、数值和进度着色；同一模型的多个额度窗口属于同一信息组，不显示额外的 `Limit:` 组标签，也不用 `|` 分隔组内字段。默认 70/30 窗格使用统一 8 格短进度条，宽度至少 110 列时可增加到 12 格；不得按剩余宽度把单条进度无限拉长。可用额度窗口与 `Ctx` 优先合并为一行；空间不足时先把进度条逐级缩短到 4 格，再隐藏重置时间和 `Ctx` 容量，然后退化为纯百分比，最后才隐藏整个 `Ctx` 组。其他未知值只显示 `--`，不得用空进度条暗示 0%。
- 高度至少 10 行时使用两行状态区并保留正文间隔；高度 6～9 行时使用两行紧凑状态区且不留空行；高度 3～5 行时使用单行紧凑底栏；高度不足 3 行时优先正文。已获得指标后，日常状态区不得扩展到第三行。
- 任一状态栏行不得超过显示宽度；标题行先隐藏模型标签、Git 统计和分支；指标行先缩短进度条，再隐藏重置时间和 `Ctx` 容量，随后退化为百分比，最后才隐藏 `Ctx`。核心 `Total` 与当前适用额度窗口优先于 Ctx；重置时间只保留最大的有效时间单位。

## 交互

| 行为 | 按键 |
|---|---|
| 选择上一／下一条提示词 | `↑`、`↓`、`k`、`j` |
| 提示词翻页 | `PgUp`、`PgDn` |
| 第一条 | `Home` |
| 最新一条 | `End` |
| 展开／折叠当前长提示词 | `Enter` |
| 折叠全部长提示词 | `c` |
| 打开 Settings | `s` |
| Settings 中选择／打开 | `↑`／`↓`、单击、`Enter` |
| Help／About 翻页 | `↑`／`↓`、`PgUp`／`PgDn` |
| 从 Help／About／Theme 返回 Settings | `Esc` |
| 在 Theme 预览／保存主题 | `↑`／`↓`、单击主题行、`Enter` |
| 关闭右侧 viewer 窗格 | `Ctrl+X` |
| 退出整个工作区 | 关闭终端或使用 Zellij 的 `Ctrl+Q` |
| 选中可见提示词 | 左键点击该提示词的可见正文行 |
| 选择并复制可见文字 | 在正文、Help、About 或 Theme 内容中按住左键拖动，松开后自动复制 |
| 鼠标滚动 | 滚轮 |

- 启动时默认选中最新一条；恢复或清空后没有提示词，不显示选中样式；上下文压缩保持当前选择。
- 上下移动焦点时自动保证焦点项可见。`PgUp`／`PgDn` 和鼠标滚轮只移动视口并暂停自动跟随，不改变当前焦点 prompt；即使滚到列表底部也不得自动聚焦最新项或恢复跟随，焦点项可以暂时位于视口外。视口位于真正底部时，新提示词到达仍随底部向下滚动，当前焦点保持不变。
- 左键按下时只记录候选点击和拖选锚点，不立即改变提示词选择；在同一单元格松开后才执行单击选择。点击旧提示词正文只改变选择并暂停跟随，不跳动已在阅读的视口；点击最新提示词恢复跟随并回到底部；正文外空白、底栏和极窄模式点击无效。Theme 页面单击主题所在行只切换预览，不保存设置。
- 双击不增加额外行为，只会重复选中同一条提示词；长提示词只能通过 `Enter` 展开／折叠。
- 在正文、Help、About 或 Theme 内容中按住左键拖动时，彩色模式以明确的前景色和背景色高亮当前选择，避免终端反色属性在双宽字符样式边界留下半格残影；`NO_COLOR` 下使用反色高亮。松开左键后通过终端 OSC 52 将所选的当前可见文字自动写入系统剪贴板。选择按显示单元格和字素簇计算，端点落在中文双宽字符内部时必须扩展到完整字素；保留跨行换行与 Unicode，不读取视口外、折叠、历史或底栏内容，也不自动滚动视口。
- 鼠标移动到不同单元格后即取消候选点击；起点在可见正文、Help、About 或 Theme 内容内时进入文字拖选，不改变当前提示词或主题选择。键盘输入、滚轮、resize、快照更新和页面切换会清除候选点击与文字选择。
- 位于最新一条时自动跟随并选中新提示词。
- 用户选择旧提示词或滚动正文后暂停跟随；视口离开底部时，在状态栏上方单独显示左对齐的下方内容提示，其左边缘与状态栏内容起点对齐，不显示 `End` 操作。数量从视口内最后一条可见提示词计算：中文显示“下方还有 1／N 条提示词”或“下方还有内容”，英文显示 `↓ 1 prompt below`、`↓ <n> prompts below` 或 `↓ More below`。提示使用主题强调色并加入 Theme 的语义颜色预览；Settings、Help、About 与 Theme 页面不显示该运行时提示。新提示词到达前视口位于真正底部时，只将视口推进到新的底部，不改变当前选择；视口离开底部时，新事件和 resize 只实时重算数量，不得改变当前选择和视口，即使选中项当前位于视口外。回到真正底部后立即隐藏提示。
- `End` 选择最新一条、回到底部并恢复跟随。
- Settings、Help、About 与 Theme 按统一网格排版：区块标题左对齐，所有正文统一缩进 2 格；快捷键、设置项、主题名、语义预览和说明共享正文起点。四个页面都不改变 prompt 的选择、展开、滚动或跟随状态；日常底栏按界面语言只显示 `[s] 设置` 或 `[s] settings`。
- 选中短提示词时 `Enter` 不执行操作，页脚不显示展开提示。
- 极窄模式暂时隐藏选中样式，恢复宽度后保持原选择。
- 新事件不得夺取左侧 Codex 焦点。
- 终端或中间层不支持 OSC 52 时，用户仍可按住 `Shift` 使用终端原生拖选与复制；viewer 不覆盖 Zellij 的剪贴板配置，并继续保留普通滚轮滚动。
- Prompt Pane 创建的 Zellij 会话固定使用 `mouse_click_through=true`，首次按下右侧正文即可同时聚焦 viewer 并开始单击／拖选；该会话中的左侧 Codex 也接收其首次聚焦点击。程序不启用 `focus_follows_mouse`，鼠标仅经过窗格不得转移键盘焦点；普通 Zellij 会话和用户全局配置不受影响。
- Prompt Pane 创建的 Zellij 会话固定使用 `on_force_close=quit`；关闭终端或终端标签页时退出当前工作区及其中的 Codex、viewer，不在后台保留可重新连接的运行。该设置仅作用于本次会话，不修改用户全局 Zellij 配置。
- 不占用 `Ctrl+C`；单键 `q` 不退出 viewer；`Ctrl+X` 只产生明确的关闭请求，由命令编排层按当前 `ZELLIJ_PANE_ID` 关闭右侧窗格，左侧 Codex 继续运行并占用释放的空间，不得退出整个工作区或强制终止 Codex。viewer 初始化、IPC 或 TUI 失败不得关闭右侧窗格，必须保留可见错误。
- 就绪态只能陈述提示词链路尚未被事件确认，不得把原因直接归结为 Hook 未启用或未信任；排障页只能引导用户使用 Codex 自带的 `/hooks` 审查流程，不得提供绕过信任检查的快捷键或自动确认。

## 文本与安全

- 保留 Unicode、中文、emoji、换行和有意义空白；按字素簇换行，不得拆开组合字符、肤色修饰、旗帜或 ZWJ emoji。
- `CRLF` 规范化为显示换行，tab 展开为固定空格。
- ANSI、CSI、OSC 和其他终端控制序列必须显示为安全文本或移除，不能被终端执行。
- 每次 `prompt.submitted` 都保留为独立记录；相同文本或相同 `turn_id` 均不得触发内容去重。
- 空 prompt、超限消息和缺失必需字段拒绝，错误不得回显 prompt。

## 固定尺寸验收

渲染测试至少覆盖 `20x6`、`24x10`、`32x12`、`48x20`、`80x24`，并包含中文全角字符、emoji、组合字符、多行、重复、超长文本、控制序列、响应式折叠提示、矮窗格 Settings／Help／About／Theme 滚动、设置项与主题行点击、鼠标点击映射和拖选复制。
