# Prompt Pane UI 规格

## 控制边界

Prompt Pane 控制终端单元格内的文字、颜色、换行、留白和滚动。字体、字号、字重、字间距和像素行高由终端统一控制，程序不得修改终端设置或依赖特定终端品牌。

README 建议使用等宽字体、14 号常规字重、约 1.15–1.20 行高并关闭连字，但这些不是运行前置条件。

## 统一网格与间距

viewer 的所有页面共享同一套终端网格，不为单个状态临时决定间距。统一参数为：左右内边距 1 个单元格、同一结构内部间隔 1 个单元格、并列信息列间隔 2 个单元格、独立内容块间隔 1 行。统一指相同关系使用相同间距，不要求编号槽、信息列和独立段落使用同一个数值。

- prompt 列表、空状态、会话边界提示、错误提示、帮助页和排障页的正文统一从窗口内容区第一行开始，不保留顶部空行，也不按视口高度动态垂直居中。
- 高度至少 10 行时，正文与状态栏之间固定保留 1 行；用户主动离开最新区域时，该行改为显示下方内容提示，不增加占用或移动正文。高度 3～9 行时取消固定空行并使用紧凑底栏；需要显示下方内容提示时优先保留提示与状态，暂时隐藏指标。高度少于 3 行时优先保留正文。
- prompt 编号槽左右使用 1 个单元格。帮助页区块标题保持左侧 1 格内边距，所有区块正文使用额外 2 格层级缩进；快捷键、主题名和无标签说明共享正文起点。主题箭头占用正文起点前的 2 格选择槽；快捷键／主题名与说明／色板构成两个独立信息列，标签列宽取当前布局最长快捷键或主题名，列间使用 2 个单元格。窄栏可缩短说明文字，但不得破坏正文起点。
- 页面标题与后续区块、两个 prompt、排障说明与后续步骤之间空 1 行；区块标题直接衔接所属正文或列表，同一快捷键列表的条目之间不空行。
- 底栏状态左对齐、当前主要操作右对齐，左右各保留 1 个单元格；不在底栏并列堆叠次要操作。
- 组合快捷键统一使用无额外空格的 `/`，例如 `h/Esc`、`↑/k` 和 `PgUp/PgDn`；快捷键／主题名列左对齐，说明／色板列左对齐，标签列宽由当前布局中的最长快捷键或主题名决定。

## 安装动画

- `setup codex` 显示需要处理的组件后直接执行，并在交互终端的当前输出区域内渲染动画，不进入 alternate screen、不清除既有终端内容；动画下方固定显示当前阶段、总进度和下载字节进度。没有受管组件需要更新时直接显示已是最新状态并执行最终检查，不播放动画。
- 每个方块对应最终矩形底板中的一个位置，`PROMPT PANE` 字形区域不放置方块并透出终端背景色，形成负空间镂空文字；底层必须先于上层落位并逐层向上堆积，同一层内以确定性打散顺序跨多列、多字母错峰，每批 3～6 块落下，不按整列或整字母依次填充。
- 单块下落采用确定性的重力加速；方块到达目标后向上回弹一格，再于约 220ms 的回弹阶段内落稳。首次安装的整体节奏也必须由慢到快：前段每批 3 块、下落时长与批间隔较长，随后逐步增加到每批 6 块并缩短下落时长与批间隔。顺序、分批和时长可重复测试，起始高度和延迟只做确定性的视觉错落。
- 安装进度决定可开始落位的轮廓比例；长时间阶段保留少量活动方块。安装成功后剩余方块在约 0.8 秒内补齐，完整镂空标识停留约 0.6 秒。
- 显式刷新不播放动画，直接逐行显示真实阶段、总进度和下载字节进度，事务完成后依次显示 `Refresh ready` 与 `Running final checks`；启动前自动修复使用含状态行在内不超过 5 行的紧凑局部落块，完成后在宽度允许时收束为单行 `Repair complete · Starting Codex…`。窄终端将自动修复完成文案拆成两行，不能截断关键状态；真实工作完成后的动画收尾不超过约 300ms。
- 宽度至少 110 列时用横向双单元格方块显示完整负空间 `PROMPT PANE`；宽度 60～109 列时用单元格方块显示完整名称；宽度不足 60 列时显示负空间 `PP`，无法安全渲染时只显示普通文字进度。
- 下落中方块使用弱化色，落位过程和最终标识使用统一绿色；成功时整体轻微提亮一次，不闪屏。失败时不补齐标识，已落位部分弱化，状态行优先保留完整 `[FAIL]`；`NO_COLOR` 下使用终端默认色。
- `[FAIL]` 后必须保留完整错误正文：先指出失败组件与阶段，再显示一个可执行处理方向。主程序／摘要下载提示检查 GitHub Release、网络或代理；Zellij 下载提示检查 GitHub 并在仅有系统代理时设置 `HTTPS_PROXY`，或预先安装准确版本 Zellij；权限、同名非受管文件、摘要不匹配和文件占用分别显示自身处理方向。窄终端可以换行但不得只留下错误码或笼统的 `setup failed`。
- 阶段编号、总阶段数和百分比只代表本次实际执行的环境检查、缺失组件安装与最终验证；首帧必须使用本次真实总阶段数，已就绪组件不得显示为正在安装，百分比不得倒退。
- 交互式动画、状态和完成文案共享终端中心轴；首次安装事务结束显示 `Installation ready`／`Running final checks`；显式刷新按逐行进度结束后显示 `Refresh ready`／`Running final checks`，随后逐项输出完整诊断。首次安装全部通过后显示 `Setup complete.`，并依次说明运行 `codex.pp`、提交第一条 prompt，以及未显示时打开 `/hooks` 审查并信任 Prompt Pane；刷新路径只显示可以继续运行 `codex.pp`，不重复首次信任教学。启动前自动修复结束显示 `Repair complete · Starting Codex…`。
- 非交互输出、重定向输出和渲染初始化失败必须使用逐行文本进度；动画只是反馈层，不参与安装事务或成功判断。交互动画必须在运行期间消费终端能力查询回复，并在退出前恢复终端状态，不得把 CSI 等协议回复泄漏给 Shell。

## 标准布局

```text

  1 为什么都有 .go？

  2 Bubble Tea 又是什么？

  3 从使用者角度考虑呢？使用者不需
    要安装这些吧？

 [LIVE]                              h help
```

- 正文滚动，状态和帮助入口固定在底栏；日常 viewer 不显示品牌名或顶部标题栏。
- Zellij 保留窗格边框，左侧保持原有标题，右侧外层窗格固定显示 `PROMPTS`，不显示可执行文件路径；Prompt Pane 启动的会话关闭边框悬停高亮与 resize 帮助文字，不关闭鼠标 resize，并让首次聚焦点击同时传入目标窗格。
- 初始 pane 比例固定为 70/30；程序不根据终端品牌或宽度自动改变比例，用户需要时使用 Zellij 自带的 resize 操作手动调整。
- 左右各保留 1 个单元格内边距；不画内部全宽分隔线。
- 编号槽最少预留 2 位并右对齐，达到 100 条时再按需扩展；编号槽左右各保留 1 个单元格，使其与窗格边界和正文的间距对称，正文在 1～99 条期间不得因编号位数变化而移动；续行与正文对齐，不显示竖向分隔符。
- 当前选中 prompt 的编号和全部可见正文使用主题强调色及选区底色，不显示 `>` 或循环动画；`NO_COLOR` 下以加粗区分。提示词间空行不属于选中块。
- 提示词之间空 1 行；提示词内部保留段落和有意义空行。
- 不画逐条完整边框，不显示时间、回答或工具活动。底部状态栏可显示当前会话的结构化 token、上下文、5h／7d 限额以及宽度允许时的模型信息。
- 单条提示词按终端显示宽度换行：由空白分隔的普通英文／数字单词优先整体移到下一行；中文、日文、韩文和 emoji 可以在字素边界继续填满当前行，不能因其与前方英文片段相邻而把整段移到下一行；只有单个英文／数字 token 本身超过可用宽度时才按字素簇安全拆分。换行后超过 8 行时默认保留前 6 行，并以弱化色显示剩余行数；当前选中项再按可用显示宽度补充完整或紧凑的 `Enter expand` 操作。折叠只影响当前渲染，不修改或丢弃内存中的完整 prompt。
- 每条长提示词独立保存展开状态；`Enter` 只展开或折叠当前选中项，`c` 折叠全部已展开项，不提供展开全部。
- resize、新事件和上下文压缩不得重置选择或各条提示词的展开状态；`/side`／`/btw` 临时侧聊只覆盖正文，返回父会话后恢复父提示词；恢复、清空或进入新主会话时清空选择、展开状态和旧提示词。

## 响应式布局

- 宽度至少 32 列：底栏通常显示状态和 `h help`；用户主动离开最新区域时，在状态栏上方显示完整的 `↓ <n> prompts below` 或 `↓ More below`。
- 宽度 20–31 列：底栏保留状态，下方内容提示允许按可用宽度截短，空间允许时显示 `h help`。
- 宽度少于 20 列：按单词换行显示 `Pane too narrow`，可用高度允许时不得因保留单行而截断提示；底部仍保留状态，事件继续保留，恢复宽度后重排。
- 高度规则统一遵循“统一网格与间距”，不得由 prompt、帮助或排障页面各自定义降级行为。

任何可见行都不得超过可用显示宽度；换行和带颜色文本的截断必须按终端显示单元格计算，并完整保留或关闭 ANSI 样式序列。

## 状态

- `[READY]`：Codex 与 viewer 已启动，但尚未收到 Codex `SessionStart`，因此 Hook 链路还未被事件确认；Codex 可能要到首条 prompt 才创建逻辑 session，不能据此断定 Hook 未启用或未信任。无论等待多久，正文都显示 `Waiting for your first prompt`，不得自动替换为故障或重启引导。底栏与其他状态一致显示 `h help`；Help 的 `Connection` 区块说明只有用户已经提交 prompt 但右侧仍未显示时，才依次在 Codex 中打开 `/hooks`、审查并信任 Prompt Pane、重新运行 `codex.pp`。
- `[LIVE]`：已收到 `SessionStart`，提示词链路实时接收正常；尚无 prompt 时显示 `Waiting for your first prompt`。
- `[ENDED]`：会话已退出，保留最后快照；迟到提示词不得改变快照或恢复为 `[LIVE]`。
- `[ERROR]`：本次运行不能安全继续。

状态固定显示在底栏左侧，不显示提示词总数。状态必须同时使用文字，不能只依赖颜色。

主会话结束后的不同 ID `startup`、`resume` 或 `clear` 产生空快照时，`[LIVE]` 正文显示新会话、恢复或清空完成，并说明只显示之后的新提示词；第一条新提示词到达后隐藏该提示。相同 ID 的重复 `startup` 不重置；`compact` 不显示边界提示，也不改变现有提示词和阅读状态。

`/side`／`/btw` 是临时正文覆盖层：父会话仍为 live 时收到不同 ID 的 `startup`，正文切换为侧聊 prompt，底栏继续显示 `[LIVE]` 和进入侧聊前的父会话指标。侧聊指标不得替换、隐藏或把父指标重置为等待态。若退出侧聊没有 Hook，正文可保留侧聊最后快照；父会话下一条 prompt 到达时恢复父提示词并追加该 prompt，侧聊 prompt 不再保留。真正的新主会话、`resume` 和 `clear` 才清空指标并进入等待态。

## 颜色与主题

- 全局颜色使用 Token Tracker 同源的六套主题：`mocha`、`latte`、`frappe`、`macchiato`、`nord`、`dracula`；对应 Hex 色值和语义映射不得近似替换。
- 主题统一作用于 prompt、选中效果、帮助与排障页、状态栏、Git 状态、setup／刷新反馈和错误状态，不允许页面内硬编码独立颜色。
- 默认主题为 `auto`：可确认浅色背景时使用 `latte`，其余情况使用 `mocha`。用户确认的主题名称保存到 Prompt Pane 用户配置；`PROMPT_PANE_THEME` 可临时覆盖。外层 Zellij 边框在工作区启动时使用同名内置主题，四套 Catppuccin 主题映射到对应的 Zellij `catppuccin-*` 主题；`auto` 分别使用 `catppuccin-latte` 与 `catppuccin-mocha` 适配浅色和深色背景。Help 中的实时预览不更新外层边框，保存后的主题从下一次工作区启动生效。
- 真彩色终端使用精确 24-bit RGB；不支持时由渲染层降级到 256 色；`NO_COLOR` 下移除颜色并使用字重、文字和符号保持层级。
- 未选中提示词编号与正文都使用终端正常前景色；当前选中 prompt 的编号与正文、主要操作使用主题强调色。折叠提示等真正次要信息使用弱化色，`NO_COLOR` 下以加粗区分当前选中 prompt。
- `READY` 使用强调色，表示进程已启动但提示词链路尚未确认；`LIVE` 使用成功色，`ERROR` 使用错误色，`ENDED` 使用弱化色。限额低于 50% 使用正常色，50%～79% 使用警告色，80% 及以上使用危险色。
- 不使用 Nerd Font 图标；颜色不得成为理解状态的唯一方式。

### 主题设置

- `h` 打开的帮助页直接包含主题设置，不再进入第二层页面；`↑`／`↓` 切换并实时预览，`Enter` 原子保存并应用，`Esc` 或 `h` 取消未保存预览并关闭帮助。
- 帮助页统一以 `Help` 为页面标题；`[READY]` 状态下增加 `Connection` 区块，说明首次 prompt 才开始确认 Hook，并仅在 prompt 未出现时给出 `/hooks` 排查步骤，不把正常初始状态表述为故障。区块固定按 `Connection`（仅适用时）、`Viewer`、`Navigate`、`Prompt`、`Git status`、`Theme`／`Theme preview`、`Zellij defaults`、`About` 排列，使当前 viewer 操作、状态解释和主题先于低频的复用工具说明；`Git status` 解释分支、已跟踪改动标记、相对 `HEAD` 的增删行数和未跟踪文件数；`Zellij defaults` 只列与当前 70/30 工作区直接相关的默认聚焦、鼠标／键盘 resize 和全屏操作，并说明自定义键位可能不同；`About` 固定在末尾，只显示当前版本、Codex Hooks／Zellij／Bubble Tea 技术基础、Token Tracker 视觉来源和支持环境。页面标题与各区块标题使用主题强调色，区块正文、快捷键说明和未选中的主题名称使用终端正常前景色；弱化色只用于不可用、被覆盖或语义预览中明确标记的次要信息。
- 主题列表只包含六套可保存的内置主题，不显示仅用于首次解析的 `auto`；当前配置为 `auto` 时，打开帮助页直接选中按终端背景解析出的 `latte` 或 `mocha`，保存后写入该明确主题。列表不显示 `recommended`／`current` 或中英文同义标签，只用左侧箭头表示正在预览的主题；选中箭头和主题名使用当前预览主题的紫色选择语义，名称按最长主题动态对齐。每个主题后依次显示与 Token Tracker 相同的 `green`、`yellow`、`peach`、`red`、`blue`、`sapphire`、`mauve`、`pink` 八个 `■` 方形色块；空间允许时色块间留一格，窄栏紧凑排列，极窄栏允许由视口裁切而不得退回圆点或减少颜色。`PgUp`／`PgDn` 和滚轮继续滚动帮助，切换主题时自动让当前主题保持可见，`20x6` 必须可完成预览与保存。
- 主题切换、保存和取消操作集中显示在固定页脚，主题区块不重复操作说明。宽栏显示 `↑/↓ select theme · Enter save · Esc cancel`，中栏允许省略 `select`，更窄时依次保留方向键、`Enter save` 和 `Enter`，不得因操作文案过长而隐藏整个提示。主题列表后固定显示语义预览，空间允许时标题为 `Theme preview · <name>`，极窄栏只省略标题后的主题名，不隐藏预览内容，也不读取或复用真实会话内容；状态／prompt／操作、指标、Git／弱化／错误按三个稳定语义组分行，再在组内按可用宽度换行。示例文字和数值保持不变，只随当前预览主题换色，并覆盖 `LIVE`、普通提示词、选中提示词、下方内容提示、主要操作、Total、Model、Limit、Git 分支／增删／未跟踪、弱化文字和错误状态。
- `PROMPT_PANE_THEME` 生效时帮助页显示环境覆盖来源；允许预览但不允许保存被覆盖的设置。
- 配置只保存主题名称，不得包含 prompt、会话指标、路径、凭据或历史。

## 状态栏

- 状态栏不显示 provider 和项目名。核心字段优先级为状态、会话累计 `Total`、5h、7d、上下文 `Ctx`；宽度充足时在状态后显示分支，再显示 Git 增删、重置倒计时和模型／推理强度。模型／推理强度位于标题行时直接显示值，不重复显示 `Model:` 标签。
- Git 状态使用 `branch* +N -N ?N`：`branch` 是当前分支，`*` 表示已有已跟踪改动，`+N`／`-N` 是已暂存与未暂存的已跟踪文件相对 `HEAD` 累计增删行数，`?N` 是排除 ignore 规则后的未跟踪文件数；这些数字不是文件数或领先／落后的提交数。
- `Total` 使用 provider 当前会话累计值；恢复会话可包含恢复前的累计 token，但不得恢复或显示旧 prompt。新会话和 `clear` 清空指标，`compact` 保留。
- 首次收到 `Stop` Hook 指标前，状态栏指标区必须保留并显示静态可用性说明 `Metrics available after first response`，不得把尚未提交 prompt 的正常状态表述为正在等待 Codex 回答；已收到指标后，缺失的 5h／7d 限额不显示，两者都缺失时隐藏整个 `Limit` 组，真实 `0%` 必须正常显示；其他单个不可用字段显示 `--`，不得隐藏整个指标区或用 `0` 冒充未知值。指标解析失败时保留上一次有效值；新主会话、恢复会话和 `clear` 清空旧指标并重新进入等待状态，`compact` 保留，`/side`／`/btw` 继承并冻结父会话最后一次有效指标。限额颜色阈值与主题语义一致。
- 进度使用 Token Tracker 同款前景色字符：已用部分为 `█`，剩余部分为 `░` 点阵；不得使用背景色空格渲染成连续矩形色块。字段统一使用标签在前的 `Label: value` 语序；`Limit`、5h 和 7d 属于同一信息组，不用 `|` 分隔组内字段。默认 70/30 窗格使用统一 8 格短进度条，宽度至少 110 列时可增加到 12 格；不得按剩余宽度把单条进度无限拉长。可用的 5h／7d 与 `Ctx` 优先合并为一行，空间不足时先隐藏 `Ctx` 容量、重置时间和整个 `Ctx` 组，再逐步缩短限额进度条；其他未知值只显示 `--`，不得用空进度条暗示 0%。
- 高度至少 10 行时使用两行状态区并保留正文间隔；高度 6～9 行时使用两行紧凑状态区且不留空行；高度 3～5 行时使用单行紧凑底栏；高度不足 3 行时优先正文。已获得指标后，日常状态区不得扩展到第三行。
- 任一状态栏行不得超过显示宽度；先隐藏模型标签、Git 统计、分支、重置时间和 `Ctx` 容量，再缩短进度条，最后才把进度条退化为百分比。核心 `Total`、5h 与 7d 优先于 Ctx；重置时间只保留最大的有效时间单位。

## 交互

| 行为 | 按键 |
|---|---|
| 选择上一／下一条提示词 | `↑`、`↓`、`k`、`j` |
| 翻页 | `PgUp`、`PgDn` |
| 第一条 | `Home` |
| 最新一条 | `End` |
| 展开／折叠当前长提示词 | `Enter` |
| 折叠全部长提示词 | `c` |
| 打开／关闭帮助 | `h` |
| 关闭帮助 | `Esc` |
| 在帮助页预览／保存主题 | `↑`／`↓`、`Enter` |
| 关闭右侧 viewer 窗格 | `Ctrl+X` |
| 退出整个工作区 | 关闭终端或使用 Zellij 的 `Ctrl+Q` |
| 选中可见提示词 | 左键点击正文行或其后的分隔行 |
| 选择并复制可见文字 | 在正文或帮助内容中按住左键拖动，松开后自动复制 |
| 鼠标滚动 | 滚轮 |

- 启动时默认选中最新一条；恢复或清空后没有提示词，不显示选中样式；上下文压缩保持当前选择。
- 上下选择时自动保证选中项可见。`PgUp`／`PgDn` 和鼠标滚轮只移动视口并暂停自动跟随，不改变当前选中 prompt；即使滚到列表底部也不得自动选择最新项或恢复跟随，选中项可以暂时位于视口外。视口位于真正底部时，新提示词到达仍随底部向下滚动，当前选择保持不变。
- 左键按下时只记录候选点击和拖选锚点，不立即改变提示词选择；在同一单元格松开后才执行单击选择。点击旧提示词正文或其后的单个空白分隔行只改变选择并暂停跟随，不跳动已在阅读的视口；分隔行归属其上方提示词。点击最新提示词恢复跟随并回到底部；正文外空白、底栏和极窄模式点击无效。
- 双击不增加额外行为，只会重复选中同一条提示词；长提示词只能通过 `Enter` 展开／折叠。
- 在正文或帮助内容中按住左键拖动时，彩色模式以明确的前景色和背景色高亮当前选择，避免终端反色属性在双宽字符样式边界留下半格残影；`NO_COLOR` 下使用反色高亮。松开左键后通过终端 OSC 52 将所选的当前可见文字自动写入系统剪贴板。选择按显示单元格和字素簇计算，端点落在中文双宽字符内部时必须扩展到完整字素；保留跨行换行与 Unicode，不读取视口外、折叠、历史或底栏内容，也不自动滚动视口。
- 鼠标移动到不同单元格后即取消候选点击；起点在可见正文或帮助内容内时进入文字拖选，不改变当前提示词选择。键盘输入、滚轮、resize、快照更新和帮助页切换会清除候选点击与文字选择。
- 位于最新一条时自动跟随并选中新提示词。
- 用户选择旧提示词或滚动正文后暂停跟随；视口离开底部时，在状态栏上方单独显示左对齐的下方内容提示，其左边缘与 `[LIVE]` 对齐，不显示 `End` 操作。数量从视口内最后一条可见提示词计算，后续还有一条时显示 `↓ 1 prompt below`，多条时显示 `↓ <n> prompts below`；最新提示词已经可见但其剩余正文仍在视口下方时显示 `↓ More below`。提示使用主题强调色并加入 Help 语义颜色预览；帮助页不显示该运行时提示。新提示词到达前视口位于真正底部时，只将视口推进到新的底部，不改变当前选择；视口离开底部时，新事件和 resize 只实时重算数量，不得改变当前选择和视口，即使选中项当前位于视口外。回到真正底部后立即隐藏提示。
- `End` 选择最新一条、回到底部并恢复跟随。
- `h` 打开的帮助页集中显示全部 viewer 快捷键和主题设置；`[READY]` 时先显示链路确认与排障步骤，再显示快捷键。帮助页按统一网格排版：区块标题左对齐，所有正文统一缩进 2 格；快捷键、主题名、语义预览、说明和 About 内容共享正文起点，快捷键／主题名与说明／色板共享动态标签列和 2 个单元格列间距。帮助页不改变 prompt 的选择、展开、滚动或跟随状态；内容超过可见高度时，使用 `PgUp`／`PgDn` 或滚轮独立滚动，`↑`／`↓` 专用于主题预览选择，底栏显示主题预览、保存和关闭操作；`h` 或 `Esc` 关闭帮助并取消未保存预览。日常底栏不逐项展示快捷键。
- 选中短提示词时 `Enter` 不执行操作，页脚不显示展开提示。
- 极窄模式暂时隐藏选中样式，恢复宽度后保持原选择。
- 新事件不得夺取左侧 Codex 焦点。
- 终端或中间层不支持 OSC 52 时，用户仍可按住 `Shift` 使用终端原生拖选与复制；viewer 不覆盖 Zellij 的剪贴板配置，并继续保留普通滚轮滚动。
- Prompt Pane 创建的 Zellij 会话固定使用 `mouse_click_through=true`，首次按下右侧正文即可同时聚焦 viewer 并开始单击／拖选；该会话中的左侧 Codex 也接收其首次聚焦点击。程序不启用 `focus_follows_mouse`，鼠标仅经过窗格不得转移键盘焦点；普通 Zellij 会话和用户全局配置不受影响。
- Prompt Pane 创建的 Zellij 会话固定使用 `on_force_close=quit`；关闭终端或终端标签页时退出当前工作区及其中的 Codex、viewer，不在后台保留可重新连接的运行。该设置仅作用于本次会话，不修改用户全局 Zellij 配置。
- 不占用 `Ctrl+C`；单键 `q` 不退出 viewer；`Ctrl+X` 只产生明确的关闭请求，由命令编排层按当前 `ZELLIJ_PANE_ID` 关闭右侧窗格，左侧 Codex 继续运行并占用释放的空间，不得退出整个工作区或强制终止 Codex。viewer 初始化、IPC 或 TUI 失败不得关闭右侧窗格，必须保留可见错误。
- 就绪态只能陈述提示词链路尚未被事件确认，不得把原因直接归结为 Hook 未启用或未信任；排障页只能引导用户使用 Codex 自带的 `/hooks` 审查流程，不得提供绕过信任检查的快捷键或自动确认。

## 文本与安全

- 保留 Unicode、中文、emoji、换行和有意义空白；按字素簇换行，不得拆开组合字符、肤色修饰、旗帜或 ZWJ emoji。
- `CRLF` 规范化为显示换行，tab 展开为固定空格。
- ANSI、CSI、OSC 和其他终端控制序列必须显示为安全文本或移除，不能被终端执行。
- 重复文本按不同 `turn_id` 保留，不按内容去重。
- 空 prompt、超限消息和缺失必需字段拒绝，错误不得回显 prompt。

## 固定尺寸验收

渲染测试至少覆盖 `20x6`、`24x10`、`32x12`、`48x20`、`80x24`，并包含中文全角字符、emoji、组合字符、多行、重复、超长文本、控制序列、响应式折叠提示、矮窗格帮助页滚动、鼠标点击映射和拖选复制。
